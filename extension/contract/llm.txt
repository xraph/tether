# tether/extension/contract

Import: github.com/xraph/tether/extension/contract

Tether's admin operations as a Forge dashboard contract contributor. The React plugin (`packages/plugin-tether` in forge-dashboard) is the consumer: it reads these shapes. Forge v1.13.2. The handlers call the same services as the REST API in `api/`, so validation and the broker-down rule are the same.

## Wiring

`Register(disp *dispatcher.Dispatcher, reg dashcontract.Registry, wreg dashcontract.WardenRegistry, deps Deps) error` loads the embedded `manifest.yaml`, runs `loader.Validate`, calls `reg.Register`, then registers one typed handler per intent. `Deps{Services ServicesProvider; AllowAnonymous bool; Operators bool}` where `ServicesProvider func() *api.Services` is called on every request (nil means Tether has not started). The extension implements `dashboard.ContractContributorAware` and passes `(*Extension).Services`. `ContributorName = "tether"`.

Contributor `tether`, capabilities `tether.read`, `tether.write`, app block `displayName Tether`, `slug tether`, `icon radio-tower`. 24 intents, all version 1: 10 queries (capability read) and 14 commands (capability write, each with `invalidates`).

No intent declares `requires`. Every intent has an admission check: it is registered with `dispatcher.BeforeDispatch(requireUser)`, which answers `UNAUTHENTICATED` (message "authentication required") before the handler runs unless the principal has an authenticated user (`p.User.Authenticated()`). A dashboard with `enable_auth` off, the default, sends principals with no user, so it is refused. `Deps.AllowAnonymous` (the extension's `WithInsecureDashboard()`) skips the check. The contributor is registered either way, so the plugin sees its intents and the refusal, not a missing app. The plugin should treat `UNAUTHENTICATED` as "sign in or enable dashboard auth".

## Tenant scope

After admission, every caller is either an operator or a tenant user (`caller.go`).

- Operator: `Deps.Operators` (the extension's `WithDashboardOperators()` or `dashboard_operators: true`), or `Deps.AllowAnonymous`, which implies it. An operator may name any tenant, manage tenants (`tenants.create`, `tenants.update`, `tenants.delete`) and read the node total (`overview.stats` with no `tenantId`).
- Tenant user: everyone else. Their tenant is resolved the way keysmith's contract resolves its own: a `tenant_id` claim on the principal (app from an `app_id` claim, else from the forge Scope), else the org and app of the forge Scope on the request context (the host's auth middleware sets it from the session; authsome sets `forge.NewOrgScope(app, org)`). The `(app, org)` pair maps to a Tether tenant through `Tenants.ResolveTenant`. A claim that is present but unusable refuses and never falls back to the Scope.
- `scoped(g, h)` wraps every tenant-scoped handler and rewrites the input's `tenantId` before the handler runs: a tenant user's omitted `tenantId` becomes their tenant, another tenant is `PERMISSION_DENIED`. An operator's `tenantId` passes as sent, and an omitted one becomes their own tenant when the session has one, else `PERMISSION_DENIED`.
- A tenant user with no resolvable tenant (no claim, no org in the Scope, an org with no Tether tenant) is `PERMISSION_DENIED` on every intent, `session.info` included.
- A tenant user's `tenants.list` holds their own tenant alone (an offset past it is an empty page); `tenants.create`, `tenants.update` and `tenants.delete` are `PERMISSION_DENIED` (`operatorOnly`), since limits are the operators' to set.

## Rules every intent follows

- A request whose principal has no authenticated user is `UNAUTHENTICATED`, whatever the intent (see above). This is checked first, before `tenantId` or the broker.
- A query takes its input as `params`, a command as `payload`. Both decode into the same input struct. JSON names are camelCase.
- `tenantId` is the tenant's ID string (`ttnt_...`), scoped as above. With no tenant to fall back on it is `PERMISSION_DENIED`, never "all tenants". A malformed one is `BAD_REQUEST`; an unknown one (operators only) is `NOT_FOUND`. A device, role, client or retained topic of another tenant is `NOT_FOUND`.
- `overview.stats` with no `tenantId` is the node total (sums, never rows) for an operator, and the caller's tenant for a tenant user. `session.info`, `tenants.list` and `tenants.create` take none; `tenants.get`, `tenants.update` and `tenants.delete` name their tenant with `tenantId`.
- Intents that call the broker (`overview.stats`, `clients.list`, `clients.kick`, `sessions.delete`, `retained.list`, `retained.delete`) are `UNAVAILABLE` while the broker is not running. So is every intent before Tether's Start.
- Optional update fields are pointers: `tenants.update` changes only the fields it names (`name: ""` sets an empty name). `roles.topics.set` and `devices.roles.set` replace whole lists, so the list is required (`[]` clears; absent is `BAD_REQUEST`).
- Errors are `*contract.Error`: `tether.ErrInvalidInput` and `warden.ErrRoleNotFound` are `BAD_REQUEST` (with the reason), `ErrNotFound` and `keysmith.ErrKeyNotFound` `NOT_FOUND`, `ErrConflict` and a rotate of a revoked key `CONFLICT`, `ErrTenantDisabled` and `ErrNotAuthorized` `PERMISSION_DENIED`, broker down `UNAVAILABLE` (retryable), anything else `INTERNAL` with the text "internal error" (the cause goes to `Services.Logger`).
- Lists are `{"items": [...]}`, `[]` and never null. `tenants.list` and `devices.list` page with `limit` (default 100, at most 500) and `offset`, and echo the effective `limit` and `offset`; a full page may have a next one. Negative values or a limit over 500 are `BAD_REQUEST`.
- Times are RFC 3339 strings. A command that returns nothing answers `{"ok": true}`.

## Shapes

    Tenant      {id, appId, externalId, name, enabled, limits: Limits, createdAt, updatedAt}
    Limits      {maxConnections, messagesPerSecond, burst, maxSessionExpirySeconds, maxSessions}   (all numbers, 0 = default or unlimited)
    Device      {id, tenantId, name, keyId, clientId?, roles: string[], metadata?, createdAt, updatedAt}
    Credentials {device: Device, username, password}                                   (username = keysmith key ID, password = the raw key)
    Client      {clientId, username?, deviceId?, remote?, connected, protocolVersion (4|5),
                 subscriptions: string[], connectedAt?, sessionExpirySeconds}
    Retained    {topic, size, qos}
    Stats       {scope: "node"|"tenant", tenantId?, tenants?, connected, sessions, subscriptions,
                 retained, messagesIn, messagesOut}
    TopicRules  {roleSlug, publish: string[], subscribe: string[]}                     (filters use %c and %u)
    SessionInfo {operator: boolean, tenantId?}
    Role        {slug, name, parentSlug?, publish: string[], subscribe: string[]}

`Device` never has a password. `Credentials` is the only shape that does.

## Queries

| Intent | Input | Output |
|---|---|---|
| `session.info` | `{}` | `SessionInfo`: `operator`, and `tenantId` when the session maps to a tenant. A tenant user without one is `PERMISSION_DENIED`. The plugin reads it on load to pick its pages. |
| `overview.stats` | `{tenantId?}` | `Stats`. With `tenantId` (or a tenant user without one): `scope "tenant"`, that tenant's counters on this node, no `tenants`. An operator without one: `scope "node"`, `tenants` is the tenant count, every other count is the sum over all tenants. |
| `tenants.list` | `{limit?, offset?}` | `{items: Tenant[], limit, offset}`. A tenant user sees only their own. |
| `tenants.get` | `{tenantId}` | `Tenant` |
| `devices.list` | `{tenantId, limit?, offset?}` | `{items: Device[], limit, offset}` |
| `devices.get` | `{tenantId, deviceId}` | `Device` |
| `roles.list` | `{tenantId}` | `{items: Role[]}`, every role of the tenant sorted by slug. |
| `roles.topics.get` | `{tenantId, roleSlug}` | `TopicRules`. Unknown role is `NOT_FOUND`. |
| `clients.list` | `{tenantId}` | `{items: Client[]}`: open connections and kept sessions on this node, sorted by client ID |
| `retained.list` | `{tenantId, filter?}` | `{items: Retained[]}`. `filter` defaults to `#` (everything but `$SYS`); an invalid one is `BAD_REQUEST`. |

## Commands

| Intent | Input | Output | Invalidates |
|---|---|---|---|
| `tenants.create` | `{appId, externalId, name?, limits?: Limits}` | `Tenant`. Missing `appId` or `externalId`, or a negative limit, is `BAD_REQUEST`; an `externalId` another tenant uses is `CONFLICT`. | `tenants.list`, `overview.stats` |
| `tenants.update` | `{tenantId, name?, enabled?, limits?: Limits}` | `Tenant`. `limits` replaces all five. Live connections take the new limits, or are dropped when disabled. | `tenants.list`, `tenants.get`, `clients.list`, `overview.stats` |
| `tenants.delete` | `{tenantId}` | `Ack`. `CONFLICT` while the tenant has devices, and then nothing changes. | `tenants.list`, `tenants.get`, `clients.list`, `overview.stats` |
| `devices.provision` | `{tenantId, name, clientId?, roles?: string[], expiresAt?}` | `Credentials`. `SecretResponse`: shown once, never replayed. | `devices.list` |
| `devices.rotate` | `{tenantId, deviceId, graceSeconds?}` | `Credentials`. `SecretResponse`. The old key works for `graceSeconds` (0 is keysmith's default). A revoked device is `CONFLICT`. | `devices.list`, `devices.get` |
| `devices.revoke` | `{tenantId, deviceId, reason?}` | `Ack`. The record stays; live connections end through the keysmith plugin events. | `devices.list`, `devices.get`, `clients.list`, `overview.stats` |
| `devices.delete` | `{tenantId, deviceId}` | `Ack` | `devices.list`, `devices.get`, `clients.list`, `overview.stats` |
| `devices.roles.set` | `{tenantId, deviceId, roles: string[]}` | `Device`. An unknown role is `BAD_REQUEST`. | `devices.list`, `devices.get` |
| `roles.create` | `{tenantId, slug, name?, parentSlug?, publish?: string[], subscribe?: string[]}` | `Role`. A missing or malformed slug (1 to 63 of `a-z0-9_-`), an invalid filter or an unknown parent is `BAD_REQUEST`; a slug the tenant already uses is `CONFLICT`. `name` defaults to the slug. | `roles.list`, `roles.topics.get` |
| `roles.delete` | `{tenantId, roleSlug}` | `Ack`. Unknown role is `NOT_FOUND`; `CONFLICT` while a device holds it or another role names it as its parent, and then nothing changes. | `roles.list`, `roles.topics.get` |
| `roles.topics.set` | `{tenantId, roleSlug, publish: string[], subscribe: string[]}` | `TopicRules` as stored. An invalid filter is `BAD_REQUEST`, an unknown role `NOT_FOUND`. | `roles.list`, `roles.topics.get` |
| `clients.kick` | `{tenantId, clientId}` | `Ack`. Disconnects, keeps the session. | `clients.list`, `overview.stats` |
| `sessions.delete` | `{tenantId, clientId}` | `Ack`. Disconnects and deletes the session. | `clients.list`, `overview.stats` |
| `retained.delete` | `{tenantId, topic}` | `Ack`. Nothing retained there is `NOT_FOUND`. | `retained.list`, `overview.stats` |

Every command is audited once it ran (`audit.go`): `audited` wraps the handler inside `scoped` (and `operatorOnly`), so a command the gate refuses never ran and records nothing. It emits through `Services.Emit` with `Actor` the principal's `User.Subject`, TenantID the tenant the command acted on, and Outcome failure with the error as Reason when the handler returned one. Actions: `tenants.create|update|delete` are `admin.tenant.*`, `devices.provision|rotate|revoke|delete` `admin.device.*`, `devices.roles.set` `admin.device.roles`, `roles.create|delete` `admin.role.*`, `roles.topics.set` `admin.role.topics`, `clients.kick` `admin.client.kick`, `sessions.delete` `admin.session.delete`, `retained.delete` `admin.retained.delete`. Queries record nothing.

`devices.provision` and `devices.rotate` take an idempotency key like any command, but because they are `SecretResponse` a retry with the same key (when the dashboard has an idempotency store) answers `CONFLICT` (reason `idempotency.already_ran`), not a second key and not the first one's secret. A client that loses the response rotates the device.

## Tests

`contract_test.go` registers the contract on a real dispatcher over a real stack (memory store, keysmith and warden engines, a broker on a loopback port, paho clients) and dispatches envelopes as a signed-in admin, so it checks the JSON the plugin receives: the lifecycle of tenants, the single appearance of the password, tenant scope on every device, role and client intent, the `PERMISSION_DENIED` rule over the whole manifest, broker-down answers, the node and tenant stats, and the admission check (every intent refuses an anonymous principal and a user with no subject; `AllowAnonymous` and a signed-in principal pass). The harness runs in operator mode unless a test says otherwise. `scope_test.go` covers tenant scope over the whole manifest: a tenant user reaches nothing of another tenant through any of the 24 intents, an operator is served the same requests, a tenant-less principal (no Scope, app-only Scope, unknown org, other app) is refused everything, a tenant user works in their own tenant with `tenantId` left out, a `tenant_id` claim wins over the Scope and a broken one refuses, and `AllowAnonymous` is an operator. `audit_test.go` runs all 14 commands with an audit spy (one event each, the dashboard user as actor, a failed kick as a failure) and checks a scope refusal records nothing. `manifest_test.go` loads and validates the manifest (24 intents, every command invalidates real queries, every intent has a handler). `extension/dashboard_contract_test.go` boots Forge with the real dashboard and reads `/capabilities`, and its real POST endpoint with auth off (UNAUTHENTICATED by default, served with `WithInsecureDashboard`; a signed-in user is PERMISSION_DENIED without a tenant and served with `WithDashboardOperators` or `dashboard_operators: true`), because `Registry.Register` rejects manifests that `loader.Validate` accepts and the dashboard only logs it.
