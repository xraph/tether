# tether/extension

Import: github.com/xraph/tether/extension

Tether as a Forge extension: the broker, the REST API (`api/`), and the keysmith and warden plugins (`events/`) that make live connections react to key and role changes. Forge v1.13.2, grove v1.10.1, keysmith v1.9.0, warden v1.8.1.

## Use

    t := extension.New(extension.WithAdminMiddleware(adminAuth))
    app.RegisterExtension(t.Keysmith())   // keysmithext.New + the tether plugin
    app.RegisterExtension(t.Warden())     // wardenext.New + the tether plugin
    app.RegisterExtension(t)

- `New(opts ...Option) *Extension`. `ExtensionName = "tether"`, `ExtensionVersion = tether.Version`. `Dependencies()` is `["grove", "keysmith", "warden"]`, so Forge registers and starts those first. `grove` is optional (Forge skips a dependency that is not registered); when the grove extension is there it registers first, so its database and migration registry exist at Tether's Register.
- `(*Extension).Keysmith(opts ...keysmithext.ExtOption) forge.Extension`: `keysmithext.New(append(opts, keysmithext.WithHookExtension(plugin))...)`, then `plugin.MarkWired()`, and keeps the `*keysmithext.Extension` it built. Keysmith takes plugins only at construction, so this is the only way in.
- `(*Extension).Warden(opts ...wardenext.Option) forge.Extension`: `wardenext.New(append(opts, wardenext.WithPlugin(plugin))...)`, then `MarkWired()`.
- `Broker() *broker.Broker`, `Services() *api.Services`: nil before Start.

## Config

`Config{BasePath string; DisableRoutes bool; GroveDatabase string; DisableMigrate bool; Broker broker.Config; JWT auth.JWTConfig; DashboardOperators bool; Cluster cluster.Config; RequireConfig bool}`, yaml/json snake_case (`base_path`, `disable_routes`, `grove_database`, `disable_migrate`, `broker`, `jwt`, `dashboard_operators`, `cluster`), `RequireConfig` is `yaml:"-"`. `DefaultConfig()`: `BasePath "/tether"` (`DefaultBasePath`), `Broker: broker.DefaultConfig()` (TCP `:1883`), `Cluster: cluster.DefaultConfig()` (off, embedded, heartbeat 2 s, lease 24 s, `log_max_age` 7 days). Register loads it with `LoadConfig("tether", &cfg, e.config, DefaultConfig(), e.config.RequireConfig)` (`extensions.tether`, then `tether`); an option beats the file when it differs from DefaultConfig.

Options: `WithConfig`, `WithBrokerConfig(broker.Config)`, `WithStore(store.Store)`, `WithGroveDatabase(name)`, `WithDisableMigrate()` (config `disable_migrate: true`: Start migrates nothing, and `Migrate` and `Rollback` refuse), `WithAdminMiddleware(...forge.Middleware)`, `WithInsecureAdminRoutes()`, `WithJWT(auth.JWTConfig)` (users and service accounts connect with an authsome JWT as the password, next to device keys; the `jwt:` config block does the same; a non-empty config is validated at Start, which fails with the field named), `WithoutKeysmithEvents()`, `WithoutWardenEvents()`, `WithInsecureDashboard()` (implies operator mode), `WithDashboardOperators()` (config `dashboard_operators: true`), `WithLogger(forge.Logger)` (default: the app's logger), `WithCluster(cluster.Config)` (sets `Enabled` itself, and gives a zero `Mode`, `Heartbeat`, `Lease`, `LogMaxAge`, `PullHeartbeat` or `LoadInterval` `cluster.DefaultConfig()`'s, so a literal with only NodeID, Cell and the mode's fields passes Validate; the `cluster:` block does the same, see Cell).

## Lifecycle

- Register: `BaseExtension.Register`, logger, config, then `vessel.Provide` of `*Extension`. A config section the loader cannot read (with `RequireConfig` off) is logged and the programmatic config (DefaultConfig plus the options) is used, never the bare defaults; `TestUnreadableConfigKeepsTheOptions` pins it. Last, `contribute`: under central migrations (see Migrations) it hands the store's migration group to grove's registry and sets `contributed`, so Start skips its own run. Nothing else: keysmith and warden build their engines in their own Register, which runs first.
- Start, in order:
  1. `ErrAdminAuthRequired` when routes are on, no `WithAdminMiddleware` and no `WithInsecureAdminRoutes`.
  2. `*keysmith.Engine` and `*warden.Engine` from the container. The keysmith engine must be the `Engine()` of an extension `Keysmith()` built, or Start returns `ErrKeysmithNotWired` (unless `WithoutKeysmithEvents`). `MarkWired` only says `Keysmith()` was called; a host that calls it and registers a different `keysmithext.New()` fails here, because the plugin never reached the engine the app runs.
  3. Warden plugin: if the engine's plugin registry already holds it (built by `Warden()`), nothing; else `eng.Plugins().Register(p)`. A nil registry (warden v1.8.0 makes one only for an engine with a plugin, a decision cache or the audit log, which is on by default) is `ErrWardenNotWired` unless `WithoutWardenEvents`.
  4. Store: `WithStore`, else the grove DB `GroveDatabase` names (`vessel.InjectNamed`), else the default one (`vessel.Inject`); driver `sqlite` gives `store/sqlite`, `pg` gives `store/postgres`, anything else is an error. Then `Migrate`, unless `DisableMigrate` or the group went to the central migrator in Register. Tether never closes the store.
  5. `service.NewTenants`, `service.NewDevices(..., WithSessions(broker), WithLogger(...))` (revoking or deleting a pinned device deletes its session), `auth.NewKeysmith(ks, tenants, store)` (and, when `Config.JWT` is set, `auth.NewJWT` joined as `auth.Chain(jwt, keysmith)`: that is the broker's Authenticator, while `api.Services.Auth` stays keysmith alone so `POST <base>/v1/publish` is device-only), `perm.NewLoader(wd, perm.WithLogger(...))`, `limits.New()`.
  6. In a cell, `openCell` (see Cell): connect, provision, the cluster services, the tenant cache eviction on the bus.
  7. `broker.New(cfg.Broker, Deps{..., Metrics, Cluster})`.
  8. `events.NewReactor(authn.Evict, broker)` bound to both plugins, before the broker listens. In a cell, `events.NewClusterReactor(authn.Evict, broker, control, logger)` instead.
  9. Routes unless disabled: admin group `Router().Group(BasePath)` with the admin middleware added by `Use`, and a second plain group for `POST <base>/v1/publish`; `api.Register` with `Services{..., MaxPublishPayload: b.MaxPacketSize()}` (the broker's, lowered in a cell whose NATS max_payload cannot carry the configured size) (0 means api's 1 MiB default). Its error fails Start.
  10. In a cell, the control bus's `Start`, so the node hears the cell before any client connects.
  11. `broker.Start`.
  12. In a cell, `Members.Start`, after the broker so its fence, unfence and dead-peer callbacks find a running broker. If it fails, the broker is stopped (10 s bound) and the cell closed.
  Every failure after step 6 undoes what started: plugins unbound, cell closed (Members, bus, connection, embedded server).
- Start and Stop are idempotent, serialized by a mutex: Start on a started extension returns nil with no side effects, Stop on a stopped one returns nil. It matters because `*Extension` is provided to the container and is a vessel `Starter`, so `vessel.Inject[*extension.Extension]` starts it once more. `TestInjectingTheExtensionDoesNotStartItTwice` pins it.
- Stop: unbinds the plugins, stops the broker (which handles mochi's Close deadlock and the reload retries, and closes the Router and Shared it made), then in a cell Members, the control bus and the connection (with the embedded server), in that order. Members goes after the broker: once it stops heartbeating, the peers declare the node dead after lease + 2 s and publish the delayed wills it still held (broker/llm.txt Liveness), and before that the broker must have let go of its clients. Health: broker running, store ping, and `broker.ClusterHealth` (an error wrapping `cluster.ErrFenced` while fenced, `cluster.ErrUnavailable` while the NATS connection is down or JetStream has not answered for longer than Lease/2, so a JetStream meta leader election does not fail every node's readiness at once; nil without a cell). `DashboardStatus()` (`dashboard.DashboardStatusAware`): `Version` and `Configured` true from a successful Start until Stop.

## Cell

`Config.Cluster` (`cluster:` under the tether section, or `WithCluster`) with `enabled: true` makes the node one broker of a cell (package cluster). `openCell` (cell.go):

- `cluster.Config.Validate` (Start fails with it, before anything connects). Ruling R43 lives there: in embedded mode, `embedded.listen` or `embedded.cluster_listen` on anything but loopback (an empty host binds every interface) needs `embedded.user` and `embedded.password`, which the server then requires of every client and route (Connect uses them, and they are added to route URLs without user info), or an explicit `embedded.insecure: true`.
- `cluster.Connect(ctx, cfg, logger)` (embedded mode starts the in-process nats-server; a node of an embedded cell gets JetStream once its peers are up, so start them together), then `cluster.Provision(ctx, conn, cfg, cfg.LogAge())` (30 s bound when ctx has none): the log stream's MaxAge is `cluster.log_max_age` (ruling R44, default 7 days), not the session cap.
- R44 warning: when `broker.max_session_expiry` (0: the 7 day default) exceeds `log_max_age`, a Warn names both, and each existing tenant whose own `limits.max_session_expiry` exceeds it gets a Warn too. Tenants changed later are not checked; the broker's cap bounds them.
- Built, not started: `NewSessions`, `NewLog`, `NewRetained`, `NewLoad`, `NewMembers`, `NewControl`, passed as `broker.Cluster{Conn, Config, Sessions, Log, Retained, Load, Members, Control}`. With `Load` set the broker reports its usage every `cluster.load_interval` and watches the other nodes' reports between its Start and Stop, so `CellUsage`, `RemoteConnections`, `TenantRates`, `Nodes` and the tenants' `$SYS` connection and message counts cover the whole cell (broker/llm.txt Cell usage). Router and Shared are left nil, so the broker makes them and closes them in its Stop (the broker's Router is always its own; `deliverRouted` is unexported). `events.EvictTenantsOnUpdate` with `service.Tenants.Evict` goes on the bus first, before `broker.New` subscribes the broker's handlers and the cluster reactor its own.
- `cluster.no_discovery` (R17) and every other `cluster.Config` key pass straight through.

Why `Use`: api registers on groups nested in the admin group. Since forge v1.13.0 a nested group inherits its parent's `Use` and `WithGroupMiddleware` chains alike, but forge v1.12.10 and earlier dropped `WithGroupMiddleware`, which mounted the admin routes open. `Use` was always safe. `TestAdminMiddlewareGuardsAdminRoutesOnly` pins it.

## Dashboard contract

`(*Extension).RegisterContractContributor(disp, reg, wreg)` implements `dashboard.ContractContributorAware` and calls `contract.Register` (package `extension/contract`, see its `llm.txt`) with `Deps{Services: e.Services, AllowAnonymous: insecureDashboard, Operators: config.DashboardOperators}`. The dashboard discovers it during its own Start. The handlers read `Services()` per request, so before Tether's Start they answer `UNAVAILABLE`, whichever extension started first. 24 intents under the contributor name `tether`: session info, overview, tenants, devices, roles (list, create, delete) and their topic grants, live clients and sessions, retained messages. `DashboardStatus()` feeds the dashboard's version check and setup panel.

Admission (fail closed like the REST admin API): every intent is registered with `dispatcher.BeforeDispatch(requireUser)`, which answers `UNAUTHENTICATED` unless the principal carries an authenticated user (`p.User.Authenticated()`, a non-empty `Subject`). The dashboard gives a request no user when its `enable_auth` is off (the default) and also when auth is on but the request did not authenticate, so a default setup serves nothing from this contributor. `WithInsecureDashboard()` turns the check off (`contract.Deps.AllowAnonymous`), for a dashboard only trusted callers can reach. The contributor stays registered either way, so the plugin still shows its pages and the refusal. Past the check, a signed-in user is confined to their own tenant (the tenant their session's `tenant_id` claim or forge Scope org maps to), and refused when they have none. `WithDashboardOperators()` or `dashboard_operators: true` makes every signed-in user an operator: any tenant, and `tenants.create/update/delete`. `WithInsecureDashboard()` implies it. `extension/contract/llm.txt` has the rules. `WithAdminMiddleware` guards the REST routes only and has no effect here.

## Metrics

Through the app's `forge.Metrics` (scraped as `forge_<name>`), no tenant label: `tether_connections` (gauge), `tether_messages_in_total`, `tether_messages_out_total`, `tether_auth_failures_total{reason}` (`broker.AuthReason*`: bad_credentials, not_authorized, unavailable, rate_limited, connection_limit, invalid_will, other), `tether_acl_denials_total{op}` (publish, subscribe). Names are the `Metric*` constants. The broker reports them through `broker.Metrics`.

In a cell only (registered by `newCellMetrics`, which also implements `broker.ClusterMetrics`), still no tenant label: `tether_cluster_fenced` (gauge, 1 while fenced; the broker reports it from its OnFence and OnUnfence), `tether_log_append_seconds` (histogram, send to commit of every QoS 1/2 log append that committed, from `cluster.Log.OnAppend`, any wait for the publisher's backpressure before the send included; buckets 0.5 ms to 10 s, the broker's attempt bound for a client publish), `tether_cas_lost_total` (session record writes that lost their CAS, from `cluster.Sessions.OnLostCAS`, an Acquire's internal retry included), `tether_replay_messages_total` (messages replays sent, where the broker counts `replayed`).

## Logging

The broker, mochi, perm and the API take `*slog.Logger`; `logger.go` has a `slog.Handler` over the forge logger (levels map to Debug/Info/Warn/Error, groups become dotted keys).

## Migrations

`migrations.go`. `*Extension` is a `forge.MigratableExtension`, so forge's `migrate up`, `down` and `status` cover Tether. `Migrate`, `Rollback` and `MigrationStatus` build a fresh grove orchestrator (locked, one executor per call) for the store's group: `postgres.Migrations` or `sqlite.Migrations`, both named `tether`, on the store's grove DB. A store not on grove (memory, the host's own) has no group: `Migrate` calls its `Migrate`, `MigrationStatus` returns none. `Rollback` is grove's: it undoes the newest row in `grove_migrations`, so on a shared database it works only while the newest row is Tether's. `Rollback` checks first and refuses with the newest row's group and name (`belongs to group "warden", not "tether"`) instead of grove's bare "not found in registered groups"; `TestRollbackRefusesAnotherGroupsNewestMigration` pins it.
Central migrations: when the app has `forge.WithCentralMigrations()` (or `database.central_migrations`), grove's `*extension.MigrationRegistry` is in the container (the grove extension makes it, only with its own `central_migrations` on), the store came from the container (not `WithStore`), it is on grove and `DisableMigrate` is off, Register calls `registry.Contribute(GroveDatabase, db.Driver(), group)`. Forge then runs the group in its one ordered pass between Register-all and Start-all, Start skips `Migrate`, `Migrate` reports nothing, and `Rollback` errors (use `migrate down`, which goes through the `CentralMigrator`). Any condition missing and Start migrates as before. `TestCentralMigrationsRunTheTetherGroup` pins it, against grove's extension with `WithCentralMigrations`. One trap: forge's `DisableMigrations` (`forge.WithDisableMigrations()` or `database.disable_migrations`), and `forge migrate status` and `migrate down`, which set it before Start, make grove's RunAll hook do nothing. Tether has already contributed by then, so it skips its Start migration too, and on a fresh database its tables are never created. That is the same for every group in the registry; run `migrate up` (or start without the flag) once first.

## Tests

`extension_test.go`: a Forge app with grove SQLite in a temp dir (`vessel.Provide` of `*grove.DB`, which keysmith, warden and tether all pick up), keysmith and warden with routes off, tether with `WithInsecureAdminRoutes` on `127.0.0.1:0`, the router behind httptest, paho 3.1.1 clients. Covers the round trip, revoke over REST disconnecting the client within 2 s, a role narrowed over REST dropping a subscription (warden built by the helper, and plugin registered at Start), the three Start refusals and their opt-outs (including a host that calls `Keysmith()` but registers another keysmith), admin middleware scope, metrics from the scrape, config from a YAML file, `WithStore`, Stop, and the double Start. `cluster_test.go`: one node on a one-server NATS through `WithCluster` (a REST revoke and a REST tenant disable disconnect the device through the bus); `TestTwoExtensionsFormACell` (two forge apps in one process sharing memory stores for tether, keysmith and warden, each with an embedded NATS routed to the other's with route credentials, started together: a device made through A's REST API connects to B and gets its own QoS 1 message back, a QoS 1 publish from a device on A reaches it, both healthy, fenced 0, one log append counted per node); `TestEmbeddedCellRefusesStrangers` (the embedded client port refuses no or wrong credentials); `TestClusterRefusesOpenListen` (R43, three open listens refused at Start, nothing started); `TestClusterHealthReportsFenced` (node behind `internal/chaos` with `no_discovery`, heartbeat 100 ms, lease 1 s: a blackhole makes Health wrap `cluster.ErrFenced` and the gauge read 1; the heal clears both). `dashboard_contract_test.go` boots the real dashboard next to Tether and reads `/capabilities` (the contributor, its 24 intents, `Configured` and `Version`), runs the contributor against live services, and checks the anonymous refusal both through the dispatcher and the dashboard's POST endpoint, the tenant-less refusal of a signed-in user by default, operator mode from the option and from the config file.
