# tether/extension

Import: github.com/xraph/tether/extension

Tether as a Forge extension: the broker, the REST API (`api/`), and the keysmith and warden plugins (`events/`) that make live connections react to key and role changes. Forge v1.12.10, keysmith v1.8.0, warden v1.8.0.

## Use

    t := extension.New(extension.WithAdminMiddleware(adminAuth))
    app.RegisterExtension(t.Keysmith())   // keysmithext.New + the tether plugin
    app.RegisterExtension(t.Warden())     // wardenext.New + the tether plugin
    app.RegisterExtension(t)

- `New(opts ...Option) *Extension`. `ExtensionName = "tether"`, `ExtensionVersion = tether.Version`. `Dependencies()` is `["keysmith", "warden"]`, so Forge registers and starts both first.
- `(*Extension).Keysmith(opts ...keysmithext.ExtOption) forge.Extension`: `keysmithext.New(append(opts, keysmithext.WithHookExtension(plugin))...)`, then `plugin.MarkWired()`, and keeps the `*keysmithext.Extension` it built. Keysmith takes plugins only at construction, so this is the only way in.
- `(*Extension).Warden(opts ...wardenext.Option) forge.Extension`: `wardenext.New(append(opts, wardenext.WithPlugin(plugin))...)`, then `MarkWired()`.
- `Broker() *broker.Broker`, `Services() *api.Services`: nil before Start.

## Config

`Config{BasePath string; DisableRoutes bool; GroveDatabase string; Broker broker.Config; JWT auth.JWTConfig; DashboardOperators bool; RequireConfig bool}`, yaml/json snake_case (`base_path`, `disable_routes`, `grove_database`, `broker`, `jwt`, `dashboard_operators`), `RequireConfig` is `yaml:"-"`. `DefaultConfig()`: `BasePath "/tether"` (`DefaultBasePath`), `Broker: broker.DefaultConfig()` (TCP `:1883`). Register loads it with `LoadConfig("tether", &cfg, e.config, DefaultConfig(), e.config.RequireConfig)` (`extensions.tether`, then `tether`); an option beats the file when it differs from DefaultConfig.

Options: `WithConfig`, `WithBrokerConfig(broker.Config)`, `WithStore(store.Store)`, `WithGroveDatabase(name)`, `WithAdminMiddleware(...forge.Middleware)`, `WithInsecureAdminRoutes()`, `WithJWT(auth.JWTConfig)` (users and service accounts connect with an authsome JWT as the password, next to device keys; the `jwt:` config block does the same; a non-empty config is validated at Start, which fails with the field named), `WithoutKeysmithEvents()`, `WithoutWardenEvents()`, `WithInsecureDashboard()` (implies operator mode), `WithDashboardOperators()` (config `dashboard_operators: true`), `WithLogger(forge.Logger)` (default: the app's logger).

## Lifecycle

- Register: `BaseExtension.Register`, logger, config, then `vessel.Provide` of `*Extension`. A config section the loader cannot read (with `RequireConfig` off) is logged and the programmatic config (DefaultConfig plus the options) is used, never the bare defaults; `TestUnreadableConfigKeepsTheOptions` pins it. Nothing else: keysmith and warden build their engines in their own Register, which runs first.
- Start, in order:
  1. `ErrAdminAuthRequired` when routes are on, no `WithAdminMiddleware` and no `WithInsecureAdminRoutes`.
  2. `*keysmith.Engine` and `*warden.Engine` from the container. The keysmith engine must be the `Engine()` of an extension `Keysmith()` built, or Start returns `ErrKeysmithNotWired` (unless `WithoutKeysmithEvents`). `MarkWired` only says `Keysmith()` was called; a host that calls it and registers a different `keysmithext.New()` fails here, because the plugin never reached the engine the app runs.
  3. Warden plugin: if the engine's plugin registry already holds it (built by `Warden()`), nothing; else `eng.Plugins().Register(p)`. A nil registry (warden v1.8.0 makes one only for an engine with a plugin, a decision cache or the audit log, which is on by default) is `ErrWardenNotWired` unless `WithoutWardenEvents`.
  4. Store: `WithStore`, else the grove DB `GroveDatabase` names (`vessel.InjectNamed`), else the default one (`vessel.Inject`); driver `sqlite` gives `store/sqlite`, `pg` gives `store/postgres`, anything else is an error. Then `Migrate`. Tether never closes the store.
  5. `service.NewTenants`, `service.NewDevices(..., WithSessions(broker), WithLogger(...))` (revoking or deleting a pinned device deletes its session), `auth.NewKeysmith(ks, tenants, store)` (and, when `Config.JWT` is set, `auth.NewJWT` joined as `auth.Chain(jwt, keysmith)`: that is the broker's Authenticator, while `api.Services.Auth` stays keysmith alone so `POST <base>/v1/publish` is device-only), `perm.NewLoader(wd, perm.WithLogger(...))`, `limits.New()`, `broker.New(cfg.Broker, Deps{..., Metrics})`.
  6. `events.NewReactor(authn.Evict, broker)` bound to both plugins, before the broker listens.
  7. Routes unless disabled: admin group `Router().Group(BasePath)` with the admin middleware added by `Use`, and a second plain group for `POST <base>/v1/publish`; `api.Register` with `Services{..., MaxPublishPayload: cfg.Broker.MaxPacketSize}` (0 means api's 1 MiB default). Its error fails Start.
  8. `broker.Start`.
- Start and Stop are idempotent, serialized by a mutex: Start on a started extension returns nil with no side effects, Stop on a stopped one returns nil. It matters because `*Extension` is provided to the container and is a vessel `Starter`, so `vessel.Inject[*extension.Extension]` starts it once more. `TestInjectingTheExtensionDoesNotStartItTwice` pins it.
- Stop: unbinds the plugins, stops the broker (which handles mochi's Close deadlock and the reload retries). Health: broker running and store ping. `DashboardStatus()` (`dashboard.DashboardStatusAware`): `Version` and `Configured` true from a successful Start until Stop.

Why `Use` and not `forge.WithGroupMiddleware`: api registers on groups nested in the admin group, and forge v1.12.10's `Group` copies a parent's `Use` middleware but not its `WithGroupMiddleware`. With the option the admin routes would mount open. `TestAdminMiddlewareGuardsAdminRoutesOnly` pins it.

## Dashboard contract

`(*Extension).RegisterContractContributor(disp, reg, wreg)` implements `dashboard.ContractContributorAware` and calls `contract.Register` (package `extension/contract`, see its `llm.txt`) with `Deps{Services: e.Services, AllowAnonymous: insecureDashboard, Operators: config.DashboardOperators}`. The dashboard discovers it during its own Start. The handlers read `Services()` per request, so before Tether's Start they answer `UNAVAILABLE`, whichever extension started first. 24 intents under the contributor name `tether`: session info, overview, tenants, devices, roles (list, create, delete) and their topic grants, live clients and sessions, retained messages. `DashboardStatus()` feeds the dashboard's version check and setup panel.

Admission (fail closed like the REST admin API): every intent is registered with `dispatcher.BeforeDispatch(requireUser)`, which answers `UNAUTHENTICATED` unless the principal carries an authenticated user (`p.User.Authenticated()`, a non-empty `Subject`). The dashboard gives a request no user when its `enable_auth` is off (the default) and also when auth is on but the request did not authenticate, so a default setup serves nothing from this contributor. `WithInsecureDashboard()` turns the check off (`contract.Deps.AllowAnonymous`), for a dashboard only trusted callers can reach. The contributor stays registered either way, so the plugin still shows its pages and the refusal. Past the check, a signed-in user is confined to their own tenant (the tenant their session's `tenant_id` claim or forge Scope org maps to), and refused when they have none. `WithDashboardOperators()` or `dashboard_operators: true` makes every signed-in user an operator: any tenant, and `tenants.create/update/delete`. `WithInsecureDashboard()` implies it. `extension/contract/llm.txt` has the rules. `WithAdminMiddleware` guards the REST routes only and has no effect here.

## Metrics

Through the app's `forge.Metrics` (scraped as `forge_<name>`), no tenant label: `tether_connections` (gauge), `tether_messages_in_total`, `tether_messages_out_total`, `tether_auth_failures_total{reason}` (`broker.AuthReason*`: bad_credentials, not_authorized, unavailable, rate_limited, connection_limit, invalid_will, other), `tether_acl_denials_total{op}` (publish, subscribe). Names are the `Metric*` constants. The broker reports them through `broker.Metrics`.

## Logging

The broker, mochi, perm and the API take `*slog.Logger`; `logger.go` has a `slog.Handler` over the forge logger (levels map to Debug/Info/Warn/Error, groups become dotted keys).

## Tests

`extension_test.go`: a Forge app with grove SQLite in a temp dir (`vessel.Provide` of `*grove.DB`, which keysmith, warden and tether all pick up), keysmith and warden with routes off, tether with `WithInsecureAdminRoutes` on `127.0.0.1:0`, the router behind httptest, paho 3.1.1 clients. Covers the round trip, revoke over REST disconnecting the client within 2 s, a role narrowed over REST dropping a subscription (warden built by the helper, and plugin registered at Start), the three Start refusals and their opt-outs (including a host that calls `Keysmith()` but registers another keysmith), admin middleware scope, metrics from the scrape, config from a YAML file, `WithStore`, Stop, and the double Start. `dashboard_contract_test.go` boots the real dashboard next to Tether and reads `/capabilities` (the contributor, its 24 intents, `Configured` and `Version`), runs the contributor against live services, and checks the anonymous refusal both through the dispatcher and the dashboard's POST endpoint, the tenant-less refusal of a signed-in user by default, operator mode from the option and from the config file.
