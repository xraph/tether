# tether/auth

Import: github.com/xraph/tether/auth

Turns MQTT CONNECT credentials into a tenant-scoped identity. The broker calls `Authenticator.Authenticate` from mochi's OnConnectAuthenticate hook and maps the error to a CONNACK reason code with `errors.Is`.

- `Credentials{ClientID, Username string; Password []byte; Remote string; SkipClientIDPin bool}`. `SkipClientIDPin` is for non-MQTT callers that have no client ID (the HTTP publish endpoint); the broker never sets it.
- `Identity{Tenant *tenant.Tenant; PrincipalKind, PrincipalID, Username, DeviceID, ClientID string; ExpiresAt time.Time}`. `ClientID` is the device's pinned client ID (empty when unpinned), not the one a client sent. `PrincipalKind` is `auth.PrincipalKindAPIKey` ("api_key") and `PrincipalID` the key ID for keysmith; `PrincipalKindUser` ("user") and `PrincipalKindServiceAccount` ("service_account") with the token subject as `PrincipalID` for JWT. Zero `ExpiresAt` means no expiry; the broker disconnects the client at that time. Callers get a copy.
- `Authenticator`: `Authenticate(ctx, Credentials) (*Identity, error)`.
- Errors (every failure wraps exactly one): `ErrBadCredentials` (CONNACK 0x86), `ErrNotAuthorized` (0x87), `ErrUnavailable` (0x88), `ErrRateLimited` (0x9F). `ErrUnavailable` comes only from: a device or tenant lookup failing with anything but not-found, a validator error that is not a recognised keysmith credential error, and a validator result with no key. It does NOT cover a keysmith lookup-store outage (see Known limitation).

## Keysmith

`NewKeysmith(v KeyValidator, t TenantResolver, d DeviceLookup, opts ...KeysmithOption) *Keysmith`. Satisfied by `*keysmith.Engine`, `*service.Tenants` and any `store.Store`. Username is the key ID, password the raw key.

Order of decisions:
1. Empty username or password: `ErrBadCredentials`.
2. `ValidateKey` (cache by SHA-256 of the password first). `ErrInvalidKey`, `ErrKeyInactive`, `ErrKeyExpired`, `ErrKeyRevoked`, `ErrKeySuspended` give `ErrBadCredentials`; keysmith `ErrRateLimited` and `ErrQuotaExceeded` give `ErrRateLimited` (0x9F, so the device backs off); any other validator error (and a nil result) gives `ErrUnavailable`.
3. `res.Key.ID.String()` must equal the username, else `ErrBadCredentials` (the raw key does not carry its ID).
4. `GetDeviceByKey`: not found gives `ErrNotAuthorized` (a keysmith key with no Tether device), other errors `ErrUnavailable`.
5. Tenant from `res.Key.AppID` and `res.Key.TenantID` through `TenantResolver`: not found, disabled, or not the device's tenant gives `ErrNotAuthorized`; other errors `ErrUnavailable`.
6. Device `ClientID` pin: a set pin that differs from `Credentials.ClientID` gives `ErrNotAuthorized`, unless `Credentials.SkipClientIDPin` is set (R16: then the check is skipped, on a cache hit too, and `Identity.ClientID` carries the pin so the caller can expand `%c` with it). Every other check still runs.

Known limitation: keysmith v1.8.0 `ValidateKey` returns `ErrInvalidKey` for any failure of its key lookup (`GetByHash`), a database outage included, and does the same for a cancelled context. Tether cannot tell that from a wrong key, so while keysmith's store is down every uncached device is refused with `ErrBadCredentials` (CONNACK 0x86), not `ErrUnavailable` (0x88). Cached devices keep connecting until their entry expires. `TestKeysmithLookupOutageSurfacesAsBadCredentials` pins this against the real engine and should flip to `ErrUnavailable` when keysmith distinguishes outages.

Cache: `WithCacheTTL(d)`, default 60 s, zero or less turns it off. Only successful validations are cached, and never past the key's `ExpiresAt` (or the grace window end for a rotated key, which also becomes `Identity.ExpiresAt`). A hit still checks username and client ID pin and resolves the tenant again, so a disabled tenant is refused at once. The device (pin, tenant) is read once per entry. A hit does not reach keysmith, so a revoked key, a changed device, and keysmith's rate limit and usage counting lag by up to the TTL: call `(*Keysmith).Evict(keyID)` when a key is revoked, rotated or suspended, or its device changes (`events.NewReactor` does). `Evict` drops every entry for that key ID, and a validation already in flight when it runs does not cache its result (an eviction counter is read before `ValidateKey` and checked before storing), so a revoke that lands while a CONNECT is validating cannot be undone by that CONNECT's late cache write.

## Static

`NewStatic(map[string]*Identity) Authenticator`: looks up by username, ignores the password, unknown username is `ErrBadCredentials`. For tests and examples only.

## JWT (jwt.go, jwks.go, chain.go)

`NewJWT(cfg JWTConfig, t TenantResolver) (*JWT, error)` authenticates authsome access tokens. The MQTT password is the JWT, the username must equal the token's subject (the broker expands `%u` from the CONNECT username, so it cannot be free text). `JWTConfig{JWKSURL, Issuer string; Audience, Algorithms []string; RefreshInterval, Leeway time.Duration}`, yaml/json snake_case (`jwks_url`, `issuer`, `audience`, `algorithms`, `refresh_interval`, `leeway`); `IsZero()` means off. Construction errors wrap `tether.ErrInvalidInput`: JWKS URL must be absolute http or https (http is allowed, for local dev), issuer and at least one non-empty audience are required, algorithms must be in RS256/384/512, PS256/384/512, ES256/384/512, EdDSA (default RS256, EdDSA, ES256; HS* and "none" are refused in config and never accepted), refresh default 10 min, leeway default 30 s (negative means none). The leeway only helps `nbf`: the broker refuses credentials whose `ExpiresAt` (the token's `exp`) has passed at CONNECT and disconnects at that moment, so it does not stretch `exp`.

Decisions, in order:
1. Password empty or over 8 KiB, unparseable, wrong alg (not in the list), bad signature, no `exp`, expired, not yet valid (`nbf`, with leeway), `iss` not equal to Issuer: `ErrBadCredentials`. authsome's own validator checks neither `iss` nor `aud`; this one checks both. `aud` must contain any one configured audience.
2. `sub` (falling back to `pid`) empty, or username not equal to it: `ErrBadCredentials`.
3. `pk` (default "user") other than "user" or "service_account" (agent, workload, anything else), a `cnf.jkt` claim (DPoP-bound, MQTT cannot prove it) a `client_id` claim (third-party OAuth client, its scope is not enforceable here) or an `act` claim (a delegated token, someone acting for the subject): `ErrNotAuthorized`.
4. `app_id` or `org_id` missing: `ErrNotAuthorized` naming the claim. authsome does not stamp `org_id`/`env_id` on issued tokens yet, so real tokens fail here until it does.
5. `TenantResolver.ResolveTenant(app_id, org_id)`: not found or disabled `ErrNotAuthorized`, other errors `ErrUnavailable`. The result is not cached beyond the resolver's own 30 s cache.
`Identity`: kind and `PrincipalID`/`Username` as above, `ExpiresAt` = `exp` (the broker disconnects then with 0xA0), `DeviceID` and `ClientID` empty. `SkipClientIDPin` is ignored.

JWKS: plain `net/http`, 5 s timeout, at most 3 redirects and only within the configured URL's scheme and host (a redirect to another origin fails the fetch, `ErrUnavailable`), 1 MiB body cap (`ErrUnavailable` "too large"). Keys are cached by `kid`. RSA keys under 2048 bits, symmetric keys, `use: enc` keys and malformed keys are skipped; a response with no usable key fails and never replaces good keys. A key's own JWK `alg`, when present, must equal the token's. A token without `kid` matches only when exactly one key of its algorithm family exists. Fetching: lazily on first use and when older than RefreshInterval; a failed refresh keeps the old keys and backs off 10 s; with no keys at all a failed load answers `ErrUnavailable` and is not retried for 10 s. A token naming an unknown `kid` refetches at most once a minute (`unknownKidInterval`), single-flight: concurrent callers share one request, and the request is detached from the caller's context. Unknown kid after that is `ErrBadCredentials`.

`Chain(jwt, keysmith Authenticator) Authenticator`: a password of three non-empty base64url segments whose first starts "ey" goes to jwt, everything else to keysmith. A JWT-shaped password jwt refuses is not retried on keysmith. Nil jwt returns keysmith. Credentials (SkipClientIDPin included) pass through unchanged.
