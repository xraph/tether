# tether/service

Import: github.com/xraph/tether/service

Tenant and device management.

`NewTenants(s store.Store, opts ...TenantsOption) *Tenants`. Option `WithEvictHook(fn func(id.TenantID))`: fn hears every eviction of the resolve cache (Update, on both sides of its write; Delete; Evict, which a cell's tenant.updated calls), after the service's lock is released, on the caller's goroutine. The extension hangs its metering and audit tenant cache off it. `TestEvictHookHearsEveryEviction`. Methods:
- `Create(ctx, CreateTenantInput{AppID, ExternalID, Name string; Limits tenant.Limits})`: new tenants are enabled. Empty AppID or ExternalID wraps `tether.ErrInvalidInput`; an ExternalID already used by another tenant, under this app or any other, wraps `tether.ErrConflict` (keysmith and warden isolate by tenant ID alone, so two tenants must never share one). The check scans every tenant and a mutex serialises `Create` within a process; it is not atomic across nodes sharing a store. `Update` cannot change ExternalID, so it needs no check.
- `Get(ctx, id.TenantID)`, `List(ctx, tenant.ListFilter)`.
- `Update(ctx, id.TenantID, UpdateTenantInput{Name *string; Enabled *bool; Limits *tenant.Limits})`: nil fields are untouched; evicts the resolve cache.
- `Delete(ctx, id.TenantID)`: wraps `tether.ErrConflict` while the tenant has devices (the store does not cascade); evicts the resolve cache.
- `ResolveTenant(ctx, appID, externalID)`: cached 30 s per process, copy returned, misses not cached, disabled tenants returned as is (the caller checks `Enabled`). With several broker nodes on one store, a change made through one node reaches the others within 30 s, or at once when every node calls `Evict(id.TenantID)` for it (a cell wires `events.EvictTenantsOnUpdate` to the control bus). Satisfies `auth.TenantResolver`.

## Devices

`NewDevices(s device.Store, t *Tenants, k KeyManager, r RoleAssigner, opts ...DevicesOption) *Devices`. Options: `WithSessions(SessionDeleter)` (`DeleteSession(tenantID, clientID string) error`, satisfied by `*broker.Broker`) and `WithLogger(*slog.Logger)`.
- `KeyManager` is satisfied by `*keysmith.Engine` (`CreateKey`, `RotateKey`, `RevokeKey`). `RoleAssigner` (`AssignRoleToAPIKey`, `UnassignRoleFromAPIKey`, `UnassignOtherRolesFromAPIKey(ctx, tenantID, keyID, keep []string)`) is satisfied by `*WardenRoles`; its tenant argument is the Tether tenant's `ExternalID`. Assigning a held role must be a no-op, and `UnassignOtherRolesFromAPIKey` must leave the `keep` roles assigned.
- `NewWardenRoles(eng *warden.Engine) *WardenRoles`: embeds warden's `keysmithbridge.Bridge` for assign and unassign-all, and adds `UnassignOtherRolesFromAPIKey`. That lists the key's assignments in the tenant root namespace (paged, 500) and deletes each one whose role is not a `keep` slug (slugs resolved with `GetRoleBySlug`; an unknown slug keeps nothing), mirroring the bridge's unassign: `RoleUnassigned` and an `assignment.deleted` audit event per removal, an assignment someone else removed counts as done, and `InvalidateSubject` once anything was removed. Writes are attributed to the context's actor, else service actor `tether`. Empty tenant is `warden.ErrTenantRequired`; empty key ID is an error.
- Every keysmith and warden call runs under `scope.With(ctx, tenant.AppID, tenant.ExternalID)`, whatever scope the caller's context carries. Devices only get keys this service created in the tenant's own scope; there is no way to attach an existing key.
- `Provision(ctx, tenantID, ProvisionInput{Name, ClientID string; Roles []string; ExpiresAt *time.Time}) (*Credentials, error)`: key prefix `tdk`, environment `live`, metadata `tether_device_id`; then each role is assigned; then the record is stored. `Name` is required, `ClientID` (if set) must be one topic level (no `/`, `+`, `#`, NUL) because it becomes `%c` in grants, role slugs must be non-empty (repeats are dropped); all wrap `tether.ErrInvalidInput`. After `CreateKey` the key's `AppID` and `TenantID` must equal the tenant's, else the key is revoked and Provision fails. A failed role assignment or store write unassigns the roles and revokes the key, on a context that survives the caller's cancellation (10 s cap); a rollback failure is joined onto the returned error.
- `Credentials{Device *device.Device; Username, Password string}`: Username is the key ID. Password is returned only by `Provision` and `Rotate` and is never stored.
- `Rotate(ctx, tenantID, deviceID, grace)`: reason `rotation.ReasonManual`; the username stays; the old password works for `grace`. Zero grace passes no option, so keysmith's default applies (policy grace, else 24 h); negative wraps `ErrInvalidInput`. A revoked device cannot be rotated.
- `Revoke(ctx, tenantID, deviceID, reason)`: revokes the key and keeps the record. Idempotent: an already revoked or missing key is success.
- `Delete(ctx, tenantID, deviceID)`: revoke (same tolerance), unassign every role, delete the record. On a failed step the record stays, so a second call finishes.
- With `WithSessions`, a successful `Revoke` or `Delete` of a device pinned to a client ID then deletes that client's session (`DeleteSession(tenant ID, ClientID)`), so its subscriptions stop queueing for a device that can never come back. It cannot fail the call: no session is fine, anything else (a CONNECT or another delete of the client ID in flight) is logged and the session ends when its expiry runs out. An unpinned device's client IDs are unknown to Tether, so its sessions always end by expiry.
- `SetRoles(ctx, tenantID, deviceID, roles)`: applies only the difference assign every new role (held ones are no-ops), then `UnassignOtherRolesFromAPIKey(keep = roles)`, then store the slugs on `device.Roles`. A role in both the old and the new set is never unassigned, so a connected device keeps that role's grants and subscriptions throughout (the broker reloads on every assignment event and prunes what the grants no longer allow). On any failure the stored roles are put back the same way (best effort, on a context that survives cancellation, 10 s cap) and the error is joined. `SetRoles` and `Delete` hold a per-device lock (64 stripes by device ID), so two calls on one device in this process cannot interleave their assign and unassign steps; several processes on one store still can. `Provision`'s rollback and `Delete` still use `UnassignRoleFromAPIKey`.
- `Get(ctx, tenantID, deviceID)`, `List(ctx, device.ListFilter)`: tenant scoped; another tenant's device wraps `tether.ErrNotFound`, as does every other method.
- The service does not know the auth layer. After `Revoke`, `Delete`, or `Rotate` with a short grace, call `(*auth.Keysmith).Evict(device.KeyID)` or the 60 s validation cache keeps the old key working.
- `Provision` on a disabled tenant is allowed; the broker refuses its devices at connect.
