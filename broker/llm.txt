# tether/broker

Import: github.com/xraph/tether/broker

The multi-tenant MQTT broker: one mochi-mqtt v2.7.9 server, one Tether hook. Every network client is resolved to a tenant at CONNECT, and its client ID and every topic it sends are prefixed with the tenant ID (a `ttnt_...` TypeID) server side. The prefix comes off again on every PUBLISH the client receives.

## API

- `Config{TCPAddress string; TLS *TLSConfig; WebSocketAddress string; DataDir string; MaxSessionExpiry time.Duration; MaxPacketSize uint32; MaxTopicLength int}`, yaml/json snake_case. `TLSConfig{Address, CertFile, KeyFile string}`.
- `DefaultConfig()`: TCP `:1883`, session expiry cap 7 days, packet 1 MiB, topic 1024 bytes, no TLS, no WebSocket, no persistence. `New` fills zero limits with these defaults. At least one listener is required.
- `PermLoader`: `Load(ctx, *auth.Identity) (acl.Rules, roleIDs []string, error)`. Called once per CONNECT (twice when a change was announced meanwhile, see Admin reactions) and again on every reload. roleIDs must list every role the rules came from, inherited ones included: `ReloadRole` finds connections by them. At CONNECT any error refuses with 0x88. On a reload an error wrapping `auth.ErrBadCredentials`, `auth.ErrNotAuthorized`, `tether.ErrNotFound` or `tether.ErrInvalidInput` disconnects with 0x87; any other error keeps the previous grants for now and starts a retry (see Admin reactions).
- `Deps{Auth auth.Authenticator; Perms PermLoader; Limits *limits.Limiter; Logger *slog.Logger; Metrics Metrics}`. Auth and Perms are required; nil Limits gets `limits.New()`, nil Logger discards, nil Metrics reports nothing. mochi logs through the same logger (`component=mochi`).
- `Metrics` (metrics.go): node-wide counters, no tenant. `ConnectionOpened()` when a connection takes a fresh tenant slot (`acquireSlot`), `ConnectionClosed()` when it releases it (`clientState.releaseSlot`, once); a takeover that inherits a slot reports neither, so opened minus closed is the live connection count. `MessageIn()` next to the tenant's in counter (OnPublish), `MessageOut()` next to its out counter (OnPacketEncode). `AuthFailure(reason)` on every refused CONNECT (`hook.refuse`), reason from the CONNACK code: `AuthReasonBadCredentials` "bad_credentials", `AuthReasonNotAuthorized`, `AuthReasonUnavailable`, `AuthReasonRateLimited`, `AuthReasonConnectionLimit` (0x97), `AuthReasonInvalidWill` (0x90), `AuthReasonOther`. `ACLDenied(op)` on every false OnACLCheck for a network client: `ACLOpPublish` "publish" for writes, `ACLOpSubscribe` "subscribe" for reads (SUBSCRIBE and deliveries). Called on mochi's goroutines: implementations must be concurrent-safe and quick. The extension maps them to forge metrics.
- `New(cfg, deps) (*Broker, error)`: validates, opens nothing. Errors wrap `tether.ErrInvalidInput`.
- `(*Broker).Start(ctx)`: opens its own listeners (so `Addr` is real), adds the hook, then mochi's badger storage hook when `DataDir` is set, then `lastHook`, then serves. Start once; a second call wraps `tether.ErrConflict`.
- `(*Broker).Stop(ctx)`: stops accepting, disconnects clients, waits for them, closes mochi and storage. Returns ctx's error if ctx ends first. No-op when not started or already stopped.
- `(*Broker).Running() bool`: true from a successful Start until Stop. The admin operations below answer `tether.ErrNotFound` or `tether.ErrConflict` when it is false, so a caller that must tell "stopped" from "no such thing" (the REST layer answers 503) checks it first.
- `(*Broker).Addr() net.Addr`: the TCP listener's address, nil if none.
- `(*Broker).Stats(tenantID string) Stats`: `Stats{Connected, Sessions, Subscriptions, Retained int; MessagesIn, MessagesOut uint64}` for one tenant on this node. Connected, Sessions (open plus kept offline sessions) and Subscriptions come from mochi's clients, Retained from mochi's retained messages in the tenant's namespace; each call walks both once. MessagesIn counts the tenant's PUBLISH packets that passed the ACL and the rate limit; MessagesOut counts PUBLISH packets written to the tenant's network clients ($SYS stats included). Counters start at zero with the process. Before Start and after Stop only the counters are filled.

Listeners: TCP and TLS use `net.ListenConfig` (TLS through `tls.NewListener`, TLS 1.2 minimum) wrapped in `listeners.NewNet`. WebSocket uses mochi's `listeners.NewWebsocket`, which binds `WebSocketAddress` itself and answers with subprotocol `mqtt` on any path; its real port is not exposed, so give it a fixed one.

Mochi options: `InlineClient: true`; capabilities `TopicAliasMaximum: 0`, `MaximumSessionExpiryInterval` from config (seconds), `MaximumPacketSize` from config.

## Hook (hook.go)

Provides exactly OnConnectAuthenticate, OnACLCheck, OnSessionEstablish, OnPacketRead, OnPacketEncode, OnPublish, OnWill. It must stay the only provider of OnConnectAuthenticate and OnACLCheck (mochi ORs them). A second hook, `lastHook` (ID `tether-last`), provides only OnDisconnect and is added after storage; see OnDisconnect below.

- OnConnectAuthenticate: `Auth.Authenticate` (Credentials.ClientID is the raw or mochi-assigned ID), refuse a nil or disabled tenant, refuse credentials whose `Identity.ExpiresAt` has passed (0x86), `Perms.Load`, `acl.Compile` with `Vars{ClientID: raw ID, Username}` (dropped grants logged once), refuse a will whose topic fails `topic.Valid` or the publish check, then take a tenant connection slot and register the state, unless DeleteSession is deleting the session of that namespaced client ID (the registry's `deleting` tombstone, checked and registered in one step by `addUnlessDeleting`): then 0x88. State is stored per `*mqtt.Client` (`clientState`: identity, tenant snapshot and grants are atomic pointers to immutable values, so the hot path takes no lock; `connectedAt`, `expiryCap` (the lower of the broker's cap and the tenant's `MaxSessionExpiry`, whole seconds), `sessionExpiry` (the CONNECT's session expiry held to `expiryCap`; 3.1.1 clean = 0 and persistent = `expiryCap`) and `expiryShortened` are set before the state is registered and never change). If `Broker.changes` moved while this ran, the whole authorization runs again under the state's `reloadMu`, now that the state is visible to every later reaction; a refusal then removes the state and releases the slot. Finally, when `Identity.ExpiresAt` is set, a timer disconnects the client at that time with 0xA0 (`packets.ErrMaxConnectTime`, maximum connect time); it is stopped when the state is removed (OnDisconnect, sweep, stale bind) and when another connection takes the session over (`registry.bind`).
- CONNACK codes. Mochi always answers a false OnConnectAuthenticate with 0x86, so the hook records the code it wants per client and OnPacketEncode rewrites that CONNACK's reason code (and reason string) on its way out. 5.0: 0x86 bad credentials, 0x87 not authorized (auth error, disabled tenant, will outside the grants), 0x88 unavailable (auth outage, permission load failure, no tenant, session being deleted), 0x9F auth rate limited, 0x97 tenant connection limit, 0x90 invalid will topic. 3.1.1: 0x04 for bad credentials, 0x03 for 0x88/0x97/0x9F, 0x05 for the rest.
- Slot takeover: at the tenant's limit, after sweeping closed connections, a client reconnecting with a client ID a live connection owns inherits that connection's slot (mochi is about to take the old one over), so a device can always replace its own connection.
- OnSessionEstablish: `cl.ID = <tenant>/<raw ID>` (before mochi's session lookup, so takeover, storage and `Clients` use it; nobody can collide with another tenant or with mochi's `inline` client); namespaces the will topic; sets `Props.TopicAliasMaximum = 0`; `capSessionExpiry`: a 5.0 `Props.SessionExpiryInterval` above `expiryCap` is lowered to it (mochi then builds its CONNACK from that, and OnPacketEncode adds the Session Expiry Interval property to the success CONNACK when `expiryShortened`), and a 3.1.1 persistent session gets `Props.SessionExpiryInterval = expiryCap` with the flag set (badger stores it). A client mochi assigned an ID keeps the un-prefixed one in its CONNACK.
- OnPacketRead (network clients): a 5.0 DISCONNECT that raises the session expiry above `expiryCap` is held to it. PUBLISH with an empty topic (alias only), or one failing `topic.Valid(name, false, MaxTopicLength)`, is rejected with `packets.ErrRejectPacket`, after a DISCONNECT for 5.0 clients (0x94 alias, 0x82 no topic, 0x90 invalid or too long). No ACL check ever sees it. Otherwise the topic is namespaced. SUBSCRIBE and UNSUBSCRIBE keep their filter count: valid filters are namespaced, an invalid or over-long one becomes "", which mochi refuses with 0x8F before the ACL check.
- OnACLCheck: inline client allowed. Otherwise strip the client's tenant (`topic.Strip`; outside the namespace is denied, which also hides mochi's global `$SYS/broker/...` and every other tenant's `$SYS/<tenant>/...`), strip `$share/<group>/` for reads, run `topic.Valid`, then `CanPublish` (also refusing anything starting with `$SYS`, as mochi does) or, for a read, allow the tenant's own `$SYS` (the relative name is `$SYS` or starts with `$SYS/`, exact case; no grant needed) and otherwise `CanSubscribe`. A client with no state that is closed (a kept session, live-disconnected or restored from storage) gets read access to names in the tenant of its namespaced ID only, so deliveries queue for offline sessions; the grants were checked when the subscription was made.
- OnPacketEncode: PUBLISH to a network client gets `topic.Strip`ped with its tenant and is counted as a message out for that tenant. A name that does not strip (should not happen: delivery passed the ACL) fails closed (`withhold`): the client is stopped with 0x83 implementation specific error, which closes its connection before mochi writes, and the packet becomes `$tether/withheld` with no payload and no properties, so neither the other tenant's topic nor its data leaves. Not counted.
- OnPublish: guard that the namespaced topic is still the client's after alias handling. Then one token from the tenant's budget (`limits.AllowMessage(tenant, tenant.Limits)`, per tenant per node, shared by its connections). Over the budget: a 5.0 QoS 1 publish returns the bare `packets.ErrQuotaExceeded` (PUBACK 0x97; mochi type-asserts the code, so never wrap it); everything else returns `packets.ErrRejectPacket` (dropped, no ack), because mochi publishes a 3.1.1 or QoS 0 message anyway on any other error and would answer QoS 2 with a PUBACK. Accepted publishes count as messages in. The inline client is never limited or counted.
- OnWill: mochi calls it as it is about to publish a will, which skips the publish ACL check. The will's topic is checked against the client's current grants; one no longer granted (or a client with no state) is replaced by a will on `$tether/withheld` with no payload, QoS 0, not retained, which no tenant filter matches and no ACL check passes (mochi ignores errors from this hook, so it cannot be told to drop the will).
- On the success CONNACK of a connection with `SessionPresent` (OnPacketEncode, the only point between mochi's session takeover and its resend of inflight messages): `pruneSession` removes the inherited subscriptions and queued PUBLISH inflights the connection's grants no longer allow (controller ruling R8 follow-through: an offline session receives anything in its tenant, so a grant revoked while the device was away is enforced here).
- OnDisconnect (`lastHook`): releases the slot, drops the state and closes `clientState.ended`. Mochi runs a hook event on hooks in the order they were added, so this runs after badger's OnDisconnect has written the session's final record; DeleteSession waits on `ended` before it deletes the record. Only this (and a refusal at CONNECT, via `registry.remove`) closes `ended`: `sweepClosed` and a stale `bind` move the state to the registry's `closing` map, where OnDisconnect still finds it; entries older than `closingTTL` (1 min) are forgotten, since mochi skipped OnDisconnect for them. Mochi also calls it for sessions it restores from storage; those have no state.

## Admin reactions (admin.go)

Called by the host when keys, roles or tenants change; `events.NewReactor` drives the first three from keysmith and warden plugin hooks. Each bumps `Broker.changes` (an atomic counter a CONNECT compares, see OnConnectAuthenticate), then copies the matching states under the registry read lock and works on them after releasing it; a PermLoader call never runs under the registry lock. Work runs in the caller's goroutine. Before Start and after Stop they do nothing.

- `DisconnectPrincipal(principalID string, code packets.Code) int`: disconnects every live connection whose identity's `PrincipalID` equals principalID (5.0 clients get a DISCONNECT with code) and returns the count. Principal IDs must be unique across tenants (keysmith key IDs are TypeIDs).
- `ReloadRole(ctx, roleID)`: reloads every live connection whose current grants came from roleID (the roleIDs its last Load returned).
- `ReloadPrincipal(ctx, principalID)`: reloads every live connection of that principal.
- A reload holds the state's `reloadMu`, calls `Perms.Load` with the stored identity and current tenant snapshot, compiles with the connection's raw client ID and CONNECT username, swaps the grants in, then prunes the subscriptions the new grants no longer allow: `Topics.Unsubscribe`, `cl.State.Subscriptions.Delete`, `Info.Subscriptions` decremented, and the badger hook's `OnUnsubscribed`, like an UNSUBSCRIBE without the UNSUBACK. A subscription survives exactly when a new SUBSCRIBE for it would pass (`Broker.canRead`, shared with OnACLCheck; the tenant's own `$SYS` always survives). Load errors: see PermLoader.
- Reload retries (controller ruling R14): a reload whose Load fails on an outage starts one retry loop per connection (`retryReload`), unless one is pending. It waits `retryBase` (1 s), doubling up to `retryMax` (30 s), and retries under `reloadMu` until a load works or `retryWindow` (2 min) has passed since the first failure; then the client is disconnected with 0x88 so it authorizes again on reconnect. A later reload that succeeds (or refuses) ends the pending loop (`st.retryStop` closed), and so does dropping the state (remove, sweep, takeover). `Stop` closes `retryQuit` (which also cancels a Load in flight) and waits for every loop before disconnecting clients; no loop starts after that. The three durations are unexported fields tests shorten; `pendingRetries` counts live loops.
- `disconnect` never lets the DISCONNECT write gate the close: the write runs in its own goroutine, and after `disconnectWait` (1 s) the client is stopped anyway, which closes the connection and fails a stuck write. Mochi's DisconnectClient writes before it stops the client and a write has no deadline, so a client that stops reading (while its own packets keep extending its keepalive) would otherwise block DisconnectPrincipal, UpdateTenant, a 0x87 reload and the admin call behind them. Shutdown disconnects clients in parallel for the same reason.
- `UpdateTenant(t *tenant.Tenant)`: stores a copy of t as the tenant snapshot of every live connection of t.ID, so OnPublish uses its limits from the next message; if `!t.Enabled` those connections are disconnected with 0x98. Call it after the tenant is stored and the resolver cache cleared (service.Tenants.Update does both), so a CONNECT that authorizes again reads the new tenant.
- Pruning a session (reconnect) also drops queued PUBLISH inflights outside the grants: `Inflight.Delete`, `IncreaseSendQuota`, `Info.Inflight` decremented, badger `OnQosDropped`. Mochi v2.7.9 already deletes a session's stored inflights on every takeover (the old client's `ClearInflights`), so the storage call matters only if that changes.

## Admin operations (admin.go)

For the host's admin API (Task 13 checks the caller's permissions and limits first; the broker checks none). Each takes a Tether tenant ID and client IDs and topics as the tenant's devices see them, namespaces them itself, and never lists or touches another tenant's clients, sessions or retained messages. A tenant ID that is not a canonical tenant TypeID (`id.ParseTenantID` and `String()` round-trips), an empty client ID or one with NUL, and a topic failing `topic.Valid` (with `MaxTopicLength`) are `tether.ErrInvalidInput`; the two listings return nil instead. None holds the registry lock across a mochi call.

- `ClientInfo{ClientID, Username, DeviceID, Remote string; Connected bool; ProtocolVersion byte; Subscriptions []string; ConnectedAt time.Time; SessionExpiry uint32}` (json snake_case; ConnectedAt omitzero). `RetainedInfo{Topic string; Size int; QoS byte}`.
- `Clients(tenantID) []ClientInfo`: mochi's `Clients.GetAll()` (open connections and kept sessions of disconnected persistent clients) filtered to the tenant's `<tenant>/` prefix, inline client excluded, sorted by client ID; subscriptions un-namespaced and sorted. An open connection's Username, DeviceID, ConnectedAt and SessionExpiry come from its state; an offline session gets Username and SessionExpiry from mochi's client (read only once it is closed, since mochi changes them while open), and Remote is whatever mochi kept (empty after a restore).
- `Kick(tenantID, clientID) error`: the bounded `disconnect` with 0x98. No open connection (offline session included) or not started: `tether.ErrNotFound`. The session stays.
- `DeleteSession(tenantID, clientID) error`: `registry.beginDelete` sets a tombstone on the namespaced ID (a CONNECT for it is refused with 0x88 until the delete returns) and fails with `tether.ErrConflict` when another delete of it runs or another connection for it has already registered (it may be about to inherit the session). An open connection is disconnected (0x98) and DeleteSession waits up to `endWait` (`sessionEndWait`, 2 s; tests shorten it) for `ended`, so badger's OnDisconnect write is done. If the wait runs out, a connection still open is `ErrConflict`; a closed one (mochi skipped its OnDisconnect after a failed CONNACK write, a ghost) is deleted anyway. Then, unless mochi already removed the session (clean session) or holds another client under the ID (`ErrConflict`), `purgeSession`: `unsubscribe` everything (the routine pruning uses: topic index, session, `Info.Subscriptions`, badger `OnUnsubscribed`), `cl.ClearInflights()` (fires `OnQosDropped` on every hook), `Clients.Delete` if mochi still maps the ID to that client, badger `OnClientExpired`. The session does not come back after a restart. `beforePurge` (unexported, tests only) runs just before the purge. No session or not started: `tether.ErrNotFound`. A 5.0 delayed will mochi already queued is still sent.
- `Retained(tenantID, filter) []RetainedInfo`: `Topics.Messages` on the namespaced filter, un-namespaced and re-checked with `topic.Match`, sorted by topic. A leading wildcard matches no `$` topic, so `#` never lists the tenant's `$SYS`; `$SYS/#` does. Shared filters match nothing.
- `DeleteRetained(tenantID, topic) error`: refuses `$SYS` names in any casing; `tether.ErrNotFound` when nothing is retained there (or not started); otherwise an inline publish of an empty retained message, which makes mochi delete it and call badger's `OnRetainMessage(-1)`. Subscribers receive the empty message, as with any MQTT clearing.
- `Publish(ctx, tenantID, topic, payload, qos, retain) error`: ctx error first; topic must not start with `$`; qos 0 or 1, else `ErrInvalidInput`; not started: `tether.ErrConflict`. Inline publish of a copy of payload: no ACL check, no rate limit, not counted in (deliveries count out). Mochi takes an inline publish as received at QoS 0 and delivers at min(qos, subscription QoS); every delivery still passes OnACLCheck.

## Session expiry (expiry.go)

Mochi expires a closed 5.0 session after its `Props.SessionExpiryInterval`, but a 3.1.1 session only after the broker's cap. The `$SYS` goroutine also runs `expireSessions` every second (`sessionSweepInterval`): an offline 3.1.1 persistent session whose flagged `Props.SessionExpiryInterval` has run out since `StopTime` is purged like DeleteSession does (`beginDelete` tombstone, wait for `ended` or skip, `purgeSession`). Sessions restored from storage carry the property, so they expire too. `Clients` reports a 3.1.1 offline session's expiry from the same property.

## Tenant $SYS (sys.go)

Every 10 s (`Broker.sysInterval`, unexported; tests shorten it before Start) a goroutine started by Start publishes, through mochi's inline client (`Server.Publish`, QoS 0, not retained), for each tenant with at least one open connection: `$SYS/<tenant>/clients/connected`, `.../messages/received`, `.../messages/sent`, `.../subscriptions/count`, `.../retained/count`, decimal payloads from `Stats`. Clients subscribe to `$SYS/#` (namespaced to `$SYS/<tenant>/#`) and receive `$SYS/clients/connected` and so on. Stop ends the publisher before it drains mochi. Mochi's own `$SYS/broker/...` (retained, every second) stays: no tenant filter can match it and OnACLCheck denies it to every network client.

## Mochi v2.7.9 workarounds

- `Server.Close` can deadlock: `Clients.GetByListener` read-locks twice, so a client added or deleted in between blocks it forever. `Stop` closes the listeners with a no-op closer, disconnects every client and waits for `Listeners.ClientsWg` before calling `Close`.
- When writing the success CONNACK or resending inflight messages fails, attachClient returns without OnDisconnect. When a tenant hits its connection limit, the hook sweeps that tenant's closed connections (`registry.sweepClosed`), releases their slots and retries. A reconnect with the same client ID also drops a closed previous owner (registry `bind`). A live connection's slot is never released by either.

## Tests

Package-internal (`broker_test.go`, `acl_test.go`, `admin_test.go`, `testutil_test.go`): `admin_test.go` uses `mutablePerms` (rules, role IDs and errors per username that tests change while clients are connected, plus `hold` to park a CONNECT inside Load) and `switchAuth` (identities whose expiry or refusal tests change). `aclObserver` on `Broker` is the unexported ACL spy. `acl_test.go` also calls hook methods directly on an unstarted mochi server (`unitHook`, `netClient` over `net.Pipe`). Negative delivery checks are ordered with sentinels: an inline subscription (`inlineSub`, which drops mochi's retained replay) proves a publisher's earlier fan-outs finished, then the broker publishes a sentinel that must be the subscriber's first message. 3.1.1 clients use `github.com/eclipse/paho.mqtt.golang`, 5.0 clients `github.com/eclipse/paho.golang/paho` or raw `paho.golang/packets` over a `net.Conn`. Waits are channel based with a 5 s bound. Set `TETHER_TEST_LOG=1` to see broker and mochi logs.
