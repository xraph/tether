# tether/broker

Import: github.com/xraph/tether/broker

The multi-tenant MQTT broker: one mochi-mqtt v2.7.9 server, one Tether hook. Every network client is resolved to a tenant at CONNECT, and its client ID and every topic it sends are prefixed with the tenant ID (a `ttnt_...` TypeID) server side. The prefix comes off again on every PUBLISH the client receives.

## API

- `Config{TCPAddress string; TLS *TLSConfig; WebSocketAddress string; DataDir string; MaxSessionExpiry time.Duration; MaxPacketSize uint32; MaxTopicLength int; MaxInflight uint16}`, yaml/json snake_case. `TLSConfig{Address, CertFile, KeyFile string}`.
- `DefaultConfig()`: TCP `:1883`, session expiry cap 7 days, packet 1 MiB, topic 1024 bytes, 1024 in-flight messages per client (`DefaultMaxInflight`, mochi's `Capabilities.MaximumInflight`; mochi's own default is 8192), no TLS, no WebSocket, no persistence. `New` fills zero limits with these defaults. At least one listener is required.
- `PermLoader`: `Load(ctx, *auth.Identity) (acl.Rules, roleIDs []string, error)`. Called once per CONNECT (twice when a change was announced meanwhile, see Admin reactions) and again on every reload. roleIDs must list every role the rules came from, inherited ones included: `ReloadRole` finds connections by them. At CONNECT any error refuses with 0x88. On a reload an error wrapping `auth.ErrBadCredentials`, `auth.ErrNotAuthorized`, `tether.ErrNotFound` or `tether.ErrInvalidInput` disconnects with 0x87; any other error keeps the previous grants for now and starts a retry (see Admin reactions).
- `Deps{Auth auth.Authenticator; Perms PermLoader; Limits *limits.Limiter; Logger *slog.Logger; Metrics Metrics; Cluster *Cluster}`. Auth and Perms are required; nil Limits gets `limits.New()`, nil Logger discards, nil Metrics reports nothing. mochi logs through the same logger (`component=mochi`). Nil Cluster runs the broker alone, exactly as before clustering existed; see Cluster mode below.
- `Metrics` (metrics.go): node-wide counters, no tenant. `ConnectionOpened()` when a connection takes a fresh tenant slot (`acquireSlot`), `ConnectionClosed()` when it releases it (`clientState.releaseSlot`, once); a takeover that inherits a slot reports neither, so opened minus closed is the live connection count. `MessageIn()` next to the tenant's in counter (OnPublish), `MessageOut()` next to its out counter (OnPacketEncode). `AuthFailure(reason)` on every refused CONNECT (`hook.refuse`), reason from the CONNACK code: `AuthReasonBadCredentials` "bad_credentials", `AuthReasonNotAuthorized`, `AuthReasonUnavailable`, `AuthReasonRateLimited`, `AuthReasonConnectionLimit` (0x97), `AuthReasonInvalidWill` (0x90), `AuthReasonOther`. `ACLDenied(op)` on every false OnACLCheck for a network client: `ACLOpPublish` "publish" for writes, `ACLOpSubscribe` "subscribe" for reads (SUBSCRIBE and deliveries). Called on mochi's goroutines: implementations must be concurrent-safe and quick. The extension maps them to forge metrics.
- `New(cfg, deps) (*Broker, error)`: validates, opens nothing. Errors wrap `tether.ErrInvalidInput`.
- `(*Broker).Start(ctx)`: opens its own listeners (so `Addr` is real), adds the hook, then mochi's badger storage hook when `DataDir` is set and there is no cluster (with a cluster it logs one Info line and ignores `DataDir`), then `lastHook`, then (cluster mode) creates the injector, then serves, then (cluster mode) starts the idle sweep of log readers. Start once; a second call wraps `tether.ErrConflict`.
- `(*Broker).Stop(ctx)`: stops the $SYS publisher and the reload retries, stops injecting (cluster mode) and stops every log reader, stops accepting, disconnects clients (their pending QoS 1/2 acks are abandoned), waits for them, closes mochi and storage, and then closes a Router the broker made. Returns ctx's error if ctx ends first. No-op when not started or already stopped.
- `(*Broker).Running() bool`: true from a successful Start until Stop. The admin operations below answer `tether.ErrNotFound` or `tether.ErrConflict` when it is false, so a caller that must tell "stopped" from "no such thing" (the REST layer answers 503) checks it first.
- `(*Broker).Addr() net.Addr`: the TCP listener's address, nil if none.
- `(*Broker).Stats(tenantID string) Stats`: `Stats{Connected, Sessions, Subscriptions, Retained int; MessagesIn, MessagesOut uint64}` for one tenant on this node. Connected, Sessions (open plus kept offline sessions) and Subscriptions come from mochi's clients, Retained from mochi's retained messages in the tenant's namespace; each call walks both once. MessagesIn counts the tenant's PUBLISH packets that passed the ACL and the rate limit; MessagesOut counts PUBLISH packets written to the tenant's network clients ($SYS stats included). Counters start at zero with the process. Before Start and after Stop only the counters are filled.

Listeners: TCP and TLS use `net.ListenConfig` (TLS through `tls.NewListener`, TLS 1.2 minimum) wrapped in `listeners.NewNet`. WebSocket uses mochi's `listeners.NewWebsocket`, which binds `WebSocketAddress` itself and answers with subprotocol `mqtt` on any path; its real port is not exposed, so give it a fixed one.

Mochi options: `InlineClient: true`; capabilities `TopicAliasMaximum: 0`, `MaximumSessionExpiryInterval` from config (seconds), `MaximumPacketSize` and `MaximumInflight` from config.

## Hook (hook.go)

Provides exactly OnConnectAuthenticate, OnACLCheck, OnSessionEstablish, OnPacketRead, OnPacketEncode, OnPublish, OnWill, and in cluster mode also OnSubscribed, OnUnsubscribed and OnClientExpired (`clusterProvided`; `Provides` answers false for them without a cluster). It must stay the only provider of OnConnectAuthenticate and OnACLCheck (mochi ORs them). A second hook, `lastHook` (ID `tether-last`), provides only OnDisconnect and is added after storage; see OnDisconnect below. What each hook adds in cluster mode for QoS 1 and 2 is under "QoS 1 and 2 through the log" below.

- OnConnectAuthenticate: `Auth.Authenticate` (Credentials.ClientID is the raw or mochi-assigned ID), refuse a nil or disabled tenant, refuse credentials whose `Identity.ExpiresAt` has passed (0x86), `Perms.Load`, `acl.Compile` with `Vars{ClientID: raw ID, Username}` (dropped grants logged once), refuse a will whose topic fails `topic.Valid` or the publish check, then check the tenant's session cap (`sessionRoom`: with `Limits.MaxSessions` set, a client ID with no session in mochi's `Clients` is refused with 0x97 when the tenant already holds that many sessions, open plus kept offline; it walks mochi's clients, so it costs O(clients) per CONNECT for those tenants, and two CONNECTs racing for the last session can both pass), then take a tenant connection slot and register the state, unless DeleteSession is deleting the session of that namespaced client ID (the registry's `deleting` tombstone, checked and registered in one step by `addUnlessDeleting`): then 0x88. State is stored per `*mqtt.Client` (`clientState`: identity, tenant snapshot and grants are atomic pointers to immutable values, so the hot path takes no lock; `connectedAt`, `expiryCap` (the lower of the broker's cap and the tenant's `MaxSessionExpiry`, whole seconds), `sessionExpiry` (the CONNECT's session expiry held to `expiryCap`; 3.1.1 clean = 0 and persistent = `expiryCap`) and `expiryShortened` are set before the state is registered and never change). If `Broker.changes` moved while this ran, the whole authorization runs again under the state's `reloadMu`, now that the state is visible to every later reaction; a refusal then removes the state and releases the slot. Finally, when `Identity.ExpiresAt` is set, a timer disconnects the client at that time with 0xA0 (`packets.ErrMaxConnectTime`, maximum connect time); it is stopped when the state is removed (OnDisconnect, sweep, stale bind) and when another connection takes the session over (`registry.bind`).
- CONNACK codes. Mochi always answers a false OnConnectAuthenticate with 0x86, so the hook records the code it wants per client and OnPacketEncode rewrites that CONNACK's reason code (and reason string) on its way out. 5.0: 0x86 bad credentials, 0x87 not authorized (auth error, disabled tenant, will outside the grants), 0x88 unavailable (auth outage, permission load failure, no tenant, session being deleted), 0x9F auth rate limited, 0x97 tenant connection or session limit, 0x90 invalid will topic. 3.1.1: 0x04 for bad credentials, 0x03 for 0x88/0x97/0x9F, 0x05 for the rest.
- Slot takeover: at the tenant's limit, after sweeping closed connections, a client reconnecting with a client ID a live connection owns inherits that connection's slot (mochi is about to take the old one over), so a device can always replace its own connection. A takeover refused after that (a delete of the session in progress, or authorizing again after a change fails) gives the slot back to the old connection, which is still open (`clientState.returnSlot`; the slot state is an atomic held, transferred or released), and releases it only when the old connection has gone meanwhile.
- OnSessionEstablish: `cl.ID = <tenant>/<raw ID>` (before mochi's session lookup, so takeover, storage and `Clients` use it; nobody can collide with another tenant or with mochi's `inline` client); namespaces the will topic; sets `Props.TopicAliasMaximum = 0`; `capSessionExpiry`: a 5.0 `Props.SessionExpiryInterval` above `expiryCap` is lowered to it (mochi then builds its CONNACK from that, and OnPacketEncode adds the Session Expiry Interval property to the success CONNACK when `expiryShortened`), and a 3.1.1 persistent session gets `Props.SessionExpiryInterval = expiryCap` with the flag set (badger stores it). A client mochi assigned an ID keeps the un-prefixed one in its CONNACK.
- OnPacketRead (network clients): in cluster mode a PUBREL frees its QoS 2 receive slot and clears the session's pending entry before mochi answers it (clusterlog.go); and the topic of a PUBLISH and every SUBSCRIBE and UNSUBSCRIBE filter must also pass `subject.CheckTopic` (1024 bytes before namespacing, the cell's limit whatever `MaxTopicLength` says), refused the same way as an invalid one below (ruling R13). A 5.0 DISCONNECT that raises the session expiry above `expiryCap` is held to it. A client with no state has its DISCONNECT passed through unchanged (refusing it would end the read with an error and mochi would publish the will) and every other packet refused with `packets.ErrRejectPacket`. PUBLISH with an empty topic (alias only), or one failing `topic.Valid(name, false, MaxTopicLength)`, is rejected with `packets.ErrRejectPacket`, after a DISCONNECT for 5.0 clients (0x94 alias, 0x82 no topic, 0x90 invalid or too long). No ACL check ever sees it. Otherwise the topic is namespaced. SUBSCRIBE and UNSUBSCRIBE keep their filter count: valid filters are namespaced, an invalid or over-long one becomes "", which mochi refuses with 0x8F before the ACL check.
- OnACLCheck: inline client allowed. Otherwise strip the client's tenant (`topic.Strip`; outside the namespace is denied, which also hides mochi's global `$SYS/broker/...` and every other tenant's `$SYS/<tenant>/...`), strip `$share/<group>/` for reads, run `topic.Valid`, then `CanPublish` (also refusing anything starting with `$SYS`, as mochi does) or, for a read, allow the tenant's own `$SYS` (the relative name is `$SYS` or starts with `$SYS/`, exact case; no grant needed) and otherwise `CanSubscribe`. A client with no state that is closed (a kept session, live-disconnected or restored from storage) gets read access to names in the tenant of its namespaced ID only, so deliveries queue for offline sessions; the grants were checked when the subscription was made.
- OnPacketEncode: PUBLISH to a network client gets `topic.Strip`ped with its tenant and is counted as a message out for that tenant. A name that does not strip (should not happen: delivery passed the ACL) fails closed (`withhold`): the client is stopped with 0x83 implementation specific error, which closes its connection before mochi writes, and the packet becomes `$tether/withheld` with no payload and no properties, so neither the other tenant's topic nor its data leaves. Not counted. A PUBLISH that is delivered also has `Mods.DisallowProblemInfo` cleared: mochi v2.7.9 sets it for a client that connected with Request Problem Information 0 (paho.golang's default) and then drops the publisher's user properties from every packet, PUBLISH included, though [MQTT-3.1.2-29] only restricts the other packet types. A 5.0 subscriber gets the user properties whatever it asked for.
- OnPublish: guard that the namespaced topic is still the client's after alias handling. Then one token from the tenant's budget (`limits.AllowMessage(tenant, tenant.Limits)`, per tenant per node, shared by its connections). Over the budget: a 5.0 QoS 1 publish returns the bare `packets.ErrQuotaExceeded` (PUBACK 0x97; mochi type-asserts the code, so never wrap it); everything else returns `packets.ErrRejectPacket` (dropped, no ack), because mochi publishes a 3.1.1 or QoS 0 message anyway on any other error and would answer QoS 2 with a PUBACK. Accepted publishes count as messages in. The inline client is never limited or counted. Cluster mode: an accepted QoS 0 publish of a network client also goes to `Router.Publish` (tenant, tenant-relative topic, `clusterProps`) before mochi delivers it locally; a QoS 0 publish of mochi's inline client (the host's Publish, DevicePublish, DeleteRetained) is routed the same way unless the injector made it (recognised by pointer) or its name is the tenant's `$SYS` (per-node stats stay on the node) or no tenant's. QoS 1 and 2 go through the log instead (see "QoS 1 and 2 through the log").
- OnWill: mochi calls it as it is about to publish a will, which skips the publish ACL check. The will's topic is checked against the client's current grants; one no longer granted (or a client with no state) is replaced by a will on `$tether/withheld` with no payload, QoS 0, not retained, which no tenant filter matches and no ACL check passes (mochi ignores errors from this hook, so it cannot be told to drop the will).
- On the success CONNACK of a connection with `SessionPresent` (OnPacketEncode, the only point between mochi's session takeover and its resend of inflight messages): `pruneSession` removes the inherited subscriptions and queued PUBLISH inflights the connection's grants no longer allow (an offline session receives anything in its tenant, so a grant revoked while the device was away is enforced here).
- OnDisconnect (`lastHook`): releases the slot, drops the state and closes `clientState.ended`. Cluster mode: also closes the connection's `pubPipe` (pending QoS 1/2 publishes abandoned, no ack) and, when mochi says the session ends with the connection (`expire`) and no other client holds the ID, drops the session's pending QoS 2 entries. Mochi runs a hook event on hooks in the order they were added, so this runs after badger's OnDisconnect has written the session's final record; DeleteSession waits on `ended` before it deletes the record. Only this (and a refusal at CONNECT, via `registry.remove`) closes `ended`: `sweepClosed` and a stale `bind` move the state to the registry's `closing` map, where OnDisconnect still finds it; entries older than `closingTTL` (1 min) are forgotten, since mochi skipped OnDisconnect for them. Mochi also calls it for sessions it restores from storage; those have no state. Cluster mode: then `endSession` (see Sessions).

## Cluster mode (cluster.go)

`Cluster{Conn *cluster.Conn; Config cluster.Config; Sessions *cluster.Sessions; Log *cluster.Log; Router *cluster.Router; Members *cluster.Members}` as `Deps.Cluster`. Conn is required and Config must be enabled and pass `Validate` (else `New` wraps `tether.ErrInvalidInput`). The broker closes none of them except a Router it made. Log nil: `New` makes one on Conn (`cluster.NewLog`); Sessions nil likewise (`cluster.NewSessions`). Members is carried but not used yet (Task 10). Router nil: `New` makes one on Conn with `Config.NodeID` whose deliver is `(*Broker).DeliverRouted`, and Stop closes it after mochi is down (so the last clean sessions still release their routes). A Router you set yourself must call `DeliverRouted` from its deliver, and you close it. Later tasks add Retained, Shared and Control.

- Injector: `srv.NewClient(nil, mqtt.LocalListener, "tether-cluster", true)` with ProtocolVersion 5 (so mochi keeps the properties), created in Start just before mochi serves (so a log reader started for the first client has somewhere to deliver), never in mochi's clients map, stored in an atomic pointer; the hook recognises it by pointer (`clusterNode.isInjector`), since mochi's own inline client is inline too. `(*Broker).inject(tenantID, name, payload, qos, props, origin, seq)` builds a PUBLISH on `topic.Namespace(tenantID, name)` (the `$` rule included) with `packetProps(props)` and calls `srv.InjectPacket`, so local delivery, OnACLCheck on every delivery and the outbound stripping run as for any message; inline means no rate limit, nothing counted in, never routed or appended again. QoS 1 and 2: mochi's processPublish takes an inline publish of any QoS as already received (the inline branch fans out and returns before the receive quota, the inflight map and any ack), delivers at min(qos, subscription) and keeps no state for the injector; `PacketID` 1 only passes mochi's validation (`TestInjectQoS12KeepsNoState`). `origin` (a namespaced client ID, or "") rides in `pk.Connect.ClientIdentifier`, which a PUBLISH never uses, and OnPublish moves it into `pk.Origin` (`injectedOrigin`), because mochi overwrites the origin with the injector's ID first: that keeps No Local working for messages from the log. A read-write gate (`clusterNode.gate`) holds the server: Stop clears it before mochi shuts down, so nothing is injected into a closing server; before Start and after that inject returns `errNotInjecting`.
- `(*Broker).DeliverRouted(tenantID, name string, payload []byte, props cluster.Props)`: a routed QoS 0 message in. It comes off NATS, so it is checked: a tenant ID that is not canonical, a name failing `topic.Valid(name, false, 1024)` (wildcards, `$share`) and a name under `$SYS` in any casing are dropped and logged at Warn. Then `inject` at QoS 0. It runs on the Router's dispatch goroutines and does not block: mochi queues each delivery on the subscriber's outbound channel (dropping when full, as for any QoS 0).
- Routed QoS 0 order: the Router delivers each topic's messages in publish order even through overlapping filters (cluster ruling R19), and `inject` hands each to mochi synchronously, so per-topic order holds into mochi's outbound queues.
- Routes (refcounted Router interest). OnSubscribed (network clients only: not mochi's inline client, not the injector) takes one reference per filter mochi accepted (code below 0x80), as (client's tenant, tenant-relative filter); shared filters are skipped (Task 12). The references live in `clusterNode.routes`, keyed by namespaced client ID (the session, so a persistent takeover keeps them) then filter, at most one per session and filter, so a repeated SUBSCRIBE holds no second one. Mochi writes the SUBACK from the same `reasonCodes` slice right after OnSubscribed, so a filter whose `Router.Subscribe` fails is refused in place: code 0x80 (also the 3.1.1 failure code), mochi's subscription removed (`Topics.Unsubscribe`, `Info.Subscriptions`, `State.Subscriptions.Delete`), no retained messages (mochi skips codes from 0x80), Warn log with tenant and filter, `routeErrors` counted.
- Releases, all through `clusterNode.release(nsID, tenant, filters)` (`releaseAll` lists the session's filters and calls it): the entry is removed under `routesMu`, so each reference is given back exactly once and a repeated release does nothing. OnUnsubscribed releases the filters the session no longer holds (mochi also calls it for a refused UNSUBSCRIBE and for filters never held): an UNSUBSCRIBE, a clean session that ended (mochi's UnsubscribeClient on disconnect, Kick included), a clean takeover. OnClientExpired (mochi's 5.0 expiry deletes the session without unsubscribing it) releases all, unless another client holds the ID. `Broker.unsubscribe` (pruning after a reload or a reconnect, DeleteSession and the 3.1.1 expiry sweep through `purgeSession`) releases what it removed (`releaseRoutes`). A persistent session that goes offline is evicted from mochi, and its end releases all its references (`finish`, see Sessions); so does the end of a session that still held subscriptions out of the index for a replay.
- A reference is pending while `Router.Subscribe` runs; a release that finds it pending skips the Router and the subscriber gives it back when its call returns, so no Router call ever runs under `routesMu` or the registry lock. Router calls from a reload's pruning run under the connection's `reloadMu` (per connection). The CONNACK-time prune runs in OnPacketEncode, which mochi calls before it takes the client's write lock (`cl.Lock()` comes after encoding in `WritePacket`), so those Router calls hold no mochi lock.
- Prune racing a SUBSCRIBE: mochi stores a subscription before OnSubscribed runs, and a reload's prune (host goroutine, `reloadMu`, which the client's read loop does not take) can remove it in that window and find no reference to release. After a successful subscribe, OnSubscribed checks `cl.State.Subscriptions` again and releases the reference when the filter is gone; a prune after that finds the reference itself. release being idempotent, both may run.
- Props (ruling R3): `clusterProps(packets.Properties) cluster.Props` and `packetProps(cluster.Props) packets.Properties` map user properties (order and duplicate keys kept), content type, response topic, correlation data, message expiry and payload format (the flag becomes a non-nil pointer and back).
- Counters for tests: `clusterNode.published` (successful Router.Publish calls), `routeErrors` (failed Router calls of any kind, each also logged at Warn). `clusterNode.routed(nsID)` lists a session's routed filters.
- Retained flag on a routed QoS 0 message does not travel (Task 11): remote subscribers get it live, not retained.

## Sessions, cursors and takeover (clustersession.go, cursor.go)

Cluster mode only. Spec "Persistent sessions and cursors" and "Ownership, takeover and liveness", spike 1 answers 1 and 2.

- Ownership: every CONNECT takes its key in the session bucket (`cluster.Sessions.AcquireWith`) as the last step of OnConnectAuthenticate, after `ensureReader` (`acquireKey`, ruling R27): a lost CAS is read again; if the record still has the epoch the attempt read, the owner's own write moved the revision, so it retries with backoff (5 ms doubling to 100 ms) for up to 2 s; if the epoch moved, another CONNECT took the key: the first time (a simultaneous connect) this later one takes it over, a second time it is refused. Failure refuses 0x88 (state removed, slot returned). A resume that fails after the acquire (`loadSession`, e.g. reading the log) gives the key back (`giveBack`, ruling R28): the record as it was, owner "", no will, the previous expiry as TTL. Before that, a raw client ID failing `subject.CheckClientID` is refused 0x85 (3.1.1: 0x02) with no KV call (R13). The record written carries owner, epoch, clean flag, protocol version, username, device ID, expiry, the CONNECT's will (tenant-relative topic, for Task 10), and either the previous record's session state (resumed) or a fresh one with `Cursor` = the tenant's live position. One `session` per namespaced ID the node owns (`clusterNode.sess`, under `sessMu`); `sessionLocks` serialises the work on one ID (CONNECT from the acquire to the end of OnSessionEstablish via `clientState.sessUnlock`, a session's end, a takeover check, a delete). It is held across NATS calls, never with the registry lock.
- Tracked sessions (`session.tracked`): persistent (`sessionExpiry` > 0) or resumed from a persistent record. They have a cursor, replay, and persist; clean ones only own their key and delete it when they end (in the background, CAS on the last revision).
- Resume (`establish`, `loadSession`): no local copy and a previous record with expiry > 0 and clean start false: the subscriptions the grants still allow go to `session.loaded` (held out of mochi's index) and take their QoS 0 routes; outbound QoS 2 still in flight (`QoS2Out`) becomes the inflight of an offline mochi client built the way loadClients does (`materialize`: `NewClient(nil, listener, id, false)`, expiry, `Stop`, `Clients.Add`), PUBREL for state 1, the PUBLISH read back from the log for state 0 (one ranged replay, `fetchLogs`, own 10 s bound), each tagged with its sequence; `QoS2Done` and those sequences go to `session.skip`; the replay also passes over everything up to the record's `DoneThrough` (`skipThrough`) except its `Pending` (`redo`, minus what was restored or completed); `QoS2In` seeds `qos2In`. mochi's inheritClientSession takes the offline client (session present). A live local session of the node is handed over instead (`handOver`: the session object moves to the new connection, mochi moves subscriptions and inflight). A closed leftover in mochi, or the connection of a session lost to another node, is evicted first. A clean start replaces the old session (replay stopped, routes released).
- Cursor: highest log sequence such that every earlier message of the tenant was acked (if it matched) or did not match; QoS 0 plays no part. `deliverLog` holds `tenantTrack.mu` around each injection and then moves `livePos`. Injected packets carry the sequence in `pk.Connect.WillTopic` (`tagSeq`/`seqOf`; mochi copies it into each subscriber's packet and never encodes it), so OnQosPublish records `session.out[packetID] = seq`; PUBACK and PUBCOMP read in OnPacketRead complete it (independent of mochi's inflight bookkeeping). A live session's cursor is `max(livePos, liveFloor)` held below every delivery in `out` and below `pin`. Pins: a delivery mochi could not queue (OnPublishDropped), an inflight map full before a message (`tenantTrack.full`, `pinFull`: mochi drops silently; `noteFull` marks a full map from every path that fills it: mochi's deliveries and the replay writer; the paths outside the tenant lock, an inbound QoS 2 reservation (`commitPublish`) and a takeover's clone (`established`, with the live position `handOver` read before the clone), use `pinIfFull`, which pins a full live session at the live position read before the map grew, since the next message may already have been dropped), a packet ID mochi reused, an injection that failed (`pinAll`). So the cursor never passes an unacknowledged or dropped message. A pin does not last: `repin` takes the live session out of the index under the tenant lock and replays it from the pin (deliveries in flight, those completed after the pin and `qos2Done` marked not to send again), waiting for the window like any replay, and the session goes live again with the pin cleared (at Stop it only pins). Records carry `DoneThrough` (the base) and `Pending` (deliveries in flight and queued), so `QoS2Done` holds only completions above `DoneThrough` and stays small.
- Replay (`runReplay`, after the CONNACK and mochi's inflight resend, from OnSessionEstablished): loops `Log.Replay(pos+1, max(livePos, flipFloor))`, sending matches straight to the client (`deliverDirect`, mochi's publishToClient by hand: merged matching subscriptions, No Local, read ACL, lower QoS, identifiers, message expiry from `PublishedAt`, packet ID, inflight entry), skipping `skip`. The callback only prepares and queues: each session's replay has its own writer (`replayOut`, a 64-packet buffer drained by its own goroutine) that takes the packet ID and inflight entry (mochi's `NextPacketID` needs the client lock a blocked write holds), records the delivery and writes it; until then a queued sequence holds the cursor (`session.queued`). A full buffer or window (inflight at `MaxInflight`, or the client's Receive Maximum, queued ones counted) ends that session's Replay call (`errBackpressure`), so it leaves the tenant's shared replay consumer rather than hold it, waits for room and starts its own from its position. A replay goes live only after its writer has written everything. Starting and stopping replays is serialised per session (`replayMu`); a stop abandons the writer (it registers and writes nothing more, checked under `session.mu` with each registration) and gives what it had queued back: the position goes below the first queued sequence and the deliveries in flight above it are marked not to send again. `handOver` switches the session's client before it stops the replay, and `startReplay` starts nothing for a client that no longer serves the session. At the CONNACK of a session taken over or restored, `orderResend` gives the tagged inflight entries `Created` values in log order, since mochi resends by whole-second `Created`. Then under `tenantTrack.mu`: `pos == livePos` flips live (subscriptions into the index, `liveFloor = pos`); `pos > livePos` (the cursor came from a node further along, or `flipFloor` from restored QoS 2) waits out of the index and `deliverLog` flips it before the first message above `pos`. Per topic: missed messages in log order, then live ones, none skipped, none sent twice. SUBSCRIBE during a replay: OnSubscribed takes the new filters out of the index again (`holdOut`, under the tenant lock); the replay matches them too (it may send a message older than the subscription). A live delivery that slipped in before `holdOut` is recorded in `skip`. Known window: between mochi's `Topics.Subscribe` and OnSubscribed a live message can overtake for that filter. A client that stops reading its socket holds only its own replay (`TestStalledReplayDoesNotHoldOthers`).
- Outbound QoS 2 exactly once across takeover: OnPacketEncode writes `QoS2Out[packetID] = {seq, 0}` to the record before a tagged QoS 2 PUBLISH to a tracked session goes out (`beforeQoS2Send`), and OnPacketRead writes state 1 before mochi answers a PUBREC with PUBREL (`onPubrec`). Each is a CAS write, so once another node has the key nothing more is sent from here: a lost write disconnects 0x8E (a failed one stops the client) and the packet is blanked. PUBCOMP moves the delivery to `QoS2Done` until the cursor passes it. At the CONNACK of a resume with restored QoS 2, one more CAS write (`mayResend`) proves the key is still this node's before mochi resends; if not, nothing is resent. Costs: two session writes per outbound QoS 2 delivery, one per resume with QoS 2 in flight.
- Persistence: `runFlusher` every `flushInterval` (1 s) writes each tracked session whose record changed (`gen`) or whose cursor moved, in parallel up to `sessionWriteSlots` (64) per node; QoS 2 steps and `persistQoS2In` write at once; every write is the whole record (`snapshot`: subscriptions from the client plus `loaded`, cursor, QoS 2 maps, `qos2In`) under `session.wmu`, CAS on the last revision. A lost write marks the session lost (`lose`). The flusher also ends sessions whose connection mochi closed without OnDisconnect (after `closedGrace`, 2 s).
- End (`endSession` from lastHook.OnDisconnect, `finish`): only for the connection that still serves the session. Replay stopped; under the tenant lock the subscriptions are read, the session evicted from mochi (spike 1's direct `Topics.Unsubscribe`, `State.Subscriptions.Delete`, `Inflight.Delete`, `Clients.Delete`, counters adjusted, never UnsubscribeClient or ClearInflights; only when mochi still maps the ID to this client and it is not taken over) and its cursor frozen; only then is it taken out of `sess`. Routes released once, `qos2In` dropped after the last write. Then: lost or being deleted, nothing written; clean or expiry 0, the key deleted; persistent, the last record (owner "", no will, `DisconnectedAt`, expiry) with `Sessions.Expire` and the session's expiry as TTL (5 s bound, synchronous so a reconnect anywhere reads it; at Stop this needs NATS). Nothing is written after it (`session.done`).
- Takeover: `Sessions.WatchOwned` (started in Start, before serving, with a context that lives until Stop; only its first pass is bounded) calls `onOwnedLost`, which always starts `verifyOwner` (the CONNECT that holds the key may not have registered its session yet); `verifyOwner` takes the session's lock (so an in-progress CONNECT of this node finishes first), reads the key (a failed read is retried with backoff, 100 ms doubling to 5 s, until an answer, the session's end or Stop), and unless it still names this node at the session's epoch marks it lost (`lose`): DISCONNECT 0x8E (0x98 when the key is gone), after the connection's CONNACK, bounded by `disconnect`. Its end then evicts without writing. The new owner replays from the last cursor written (QoS 1 may repeat; QoS 2 does not).
- Concurrent CONNECTs on one node (Task 8 carry): a connection that is no longer the registry owner of its ID at its CONNACK drops what mochi cloned into it (OnPacketEncode, nothing resent) and is disconnected 0x8E in OnSessionEstablished.
- Counters for tests: `evictions`, `sessionWrites`, `takeovers`, `casRetries`, `replayed`, `replaysDone`, `repins`, `ownedEvents`. Seams: `clusterNode.afterAcquire` (runs between a CONNECT's acquire and its registration) and `loadHook` (fails `loadSession`).

## QoS 1 and 2 through the log (clusterlog.go)

In cluster mode every QoS 1 and 2 publish, a device's or the host's, is committed to the cell's log, and every node delivers QoS 1 and 2 to its own sessions only from the log (spike 1's async ack, rulings R21 to R24).

- Publish ACL in cluster mode: OnACLCheck answers true for every network client's write (mochi asks for write access only in processPublish, right before OnPublish), and OnPublish decides it with the same `aclCheck`, counting `ACLDenied(publish)`, so a refusal's ack waits its turn (R23; mochi would write its 0x87 at once). Refused: QoS 0 dropped; 3.1.1 QoS 1/2 disconnected (as mochi does); 5.0 QoS 1/2 get PUBACK or PUBREC 0x87 through the pipe (`ackNow`, after `admit`). Without a cluster nothing changes.
- Network client, OnPublish: guard, ACL (above), then `pubPipe.admit` (receive maximum, below), then the rate limit (a 5.0 QoS 1 or 2 over it gets PUBACK or PUBREC 0x97 through the pipe, `ackNow`, in order; 3.1.1 is dropped as before), then counted in, then `commitPublish` and `packets.ErrRejectPacket`: mochi neither acks, nor delivers, nor retains it. The `LogMessage` carries the connection's tenant (never anything the client sent), the tenant-relative topic, a copy of the payload, the QoS, the retain flag, `clusterProps`, `Origin` = node ID and `ClientID` = the raw client ID.
- `pubPipe` (one per connection, `clientState.pipe`, made in OnConnectAuthenticate): two goroutines started with the first QoS 1/2 publish. The starter takes publishes in arrival order and calls `Log.AppendAsync` (so one client's messages are committed in the order it sent them; QoS 2 first goes through the `persistQoS2` seam). The writer takes them in the same order, waits for each commit (`PendingAppend.Wait`, `appendAttempt` 10 s), and writes PUBACK (QoS 1) or PUBREC (QoS 2) with `cl.WritePacket`, so acks go out in arrival order even when commits finish out of order (R23). A failed or timed-out append is sent again with the same message ID (JetStream stores it once), with backoff `appendRetry` 100 ms doubling to `appendRetryMax` 5 s, while the connection is open. When the connection ends (`lastHook.OnDisconnect` closes the pipe; the waits also check `cl.Closed()`), everything pending is abandoned with no ack and the client resends it on reconnect. Nothing is acked before its commit. An append refused as invalid input (cannot happen: every topic was checked) logs at Error and closes the client with 0x83.
- PUBREC reservation (`pubPipe.reserve`): a QoS 2 publish's PUBREC goes into `cl.State.Inflight` (and `Info.Inflight`) in OnPublish, as mochi's processPublish does, so mochi's `NextPacketID` never hands that packet ID to an outbound delivery while the commit runs (mochi keeps both directions in one map; `TestQoS2SelfSubscribedKeepsDeliveries`). The writer only writes it, and mochi's own PUBREL handling answers PUBCOMP (spike 1, `TestAsyncAckQoS2`). Never an ack for an uncommitted message: `pubPipe.reserved` lists the reservations whose commit was not seen, and `close` (abandoned, under `p.mu`, with `committed` deciding each item under the same lock) removes them from the inflight map. The invariant: every path that lets mochi clone a session's inflight map for a new connection has closed the old pipe first. The registry closes it (`clientState.closePipe`, under the registry lock) before a state stops owning its namespaced ID: `bind` for a takeover (in OnSessionEstablish, before mochi's `inheritClientSession`), `remove` (OnDisconnect) and `sweepClosed`. So neither the offline session nor the inheriting connection resends a PUBREC for something not in the log, also when a reconnect comes while the old connection's OnDisconnect has not finished (`TestQoS2AbandonedLeavesNoPubrec`, `TestQoS2NoPubrecInDisconnectWindow`, which holds the old connection through the unexported `Broker.disconnectHold` seam before or after its state is removed). A committed reservation stays and is resent on reconnect, rightly: a committed QoS 2 whose PUBREC was never written gets that PUBREC resent after the CONNACK, and the client's DUP of it then gets mochi's 0x91, as on standalone mochi. A same-connection DUP of a QoS 2 publish still pending gets mochi's own PUBREC 0x91 (packet identifier in use); conforming clients resend only after a reconnect.
- Receive maximum (R22): counted against the server's advertised Receive Maximum (`Capabilities.ReceiveMaximum`, mochi's default 1024; the unexported `Broker.receiveMaximum` sets it in tests). Outstanding for a 5.0 client = publishes whose ack is not written (`pending`) plus QoS 2 packet IDs whose PUBREC is written and whose PUBREL has not been read (`held`). A 3.1.1 client counts `pending` only: its PUBREL is read by the read loop that waits in admit, so counting `held` would deadlock a QoS 2 flood. A new publish at the limit: a 5.0 client gets DISCONNECT 0x93 (`disconnect`); a 3.1.1 client waits in OnPublish (its read loop, so backpressure) until a slot frees, checking every 250 ms that it is still open, and its publish is dropped if the connection ends first. Mochi's own receive quota is never spent (OnPublish rejects first), so mochi never disconnects for it.
- QoS 2 pending entries: `clusterNode.qos2In[nsID][packetID] = msgID` (`qos2MsgID`), written in OnPublish. A DUP resend reuses the entry's message ID, so a message committed before a drop is not stored twice (within the stream's 2 minute duplicate window); a publish without DUP gets a fresh ID. OnPacketRead clears the entry on PUBREL (`pubrel`, which also frees the `held` slot) before mochi answers PUBCOMP. Dropped on a clean start (OnSessionEstablish), a session ending with its connection, OnClientExpired and `purgeSession`. For a tracked session (see Sessions) the starter writes the record (`persistQoS2` = `persistQoS2In`, a session write) before each QoS 2 append and again before each retry, so a DUP resend reaching any node finds the message ID; the entries are seeded from the record when a session is resumed from the cell, PUBREL marks the record changed, and they go once the session's last record is written. Other sessions keep them in memory.
- Retained: a retained QoS 1/2 publish is kept in this node's mochi retained store once committed (`retainLocal`, an empty payload clears), like a QoS 0 one on its node; the log carries the flag, readers deliver it live. Cell-wide retained messages are Task 11.
- Host publishes (R21): `Publish` and `DevicePublish` at QoS 1 in cluster mode check `subject.CheckTopic` (as every cluster path does, R13; QoS 0 too), `Log.Append` synchronously under the caller's ctx and return its error wrapped (`cluster.ErrUnavailable` when the log cannot be reached); every node, this one included, delivers from its reader. A retained one is also kept locally.
- Readers (R24): one `cluster.Reader` per tenant with a connection on the node (`clusterNode.readers`, under `readersMu`, never held across a Log call). `ensureReader` runs in OnConnectAuthenticate after the authorization and before the CONNACK, starting the reader from "new" (fromSeq 0) when none runs; concurrent CONNECTs of a tenant share one start; a reader that cannot start refuses the CONNECT with 0x88. `watchReader` restarts a reader whose `Done()` closed without a Stop from `Position()+1`, logged at Warn, retrying with backoff. The sweep (`readerSweep` 10 s) stops a reader whose tenant has had no open connection (`registry.liveTenants`) for `readerIdle` (1 min); offline sessions do not hold it (Task 9 replays them from their cursor). Readers are never stopped from their own fn.
- Delivery (`logDeliver`, which calls `deliverLog` in cursor.go): the reader only reads `d.<tenant>.>`, and a message whose tenant is not the reader's, whose topic fails `topic.Valid(name, false, 1024)` or is under `$SYS` in any casing, or whose QoS is not 1 or 2, is dropped at Warn. The rest is injected at its QoS with its props, `origin` = the namespaced publisher ID and its log sequence as a tag (`tagSeq`), under the tenant's delivery lock (see Sessions). The publishing node's own subscribers get the message from its own reader, once (mochi's fan-out was rejected).
- Counters for tests: `clusterNode.appends` (commits this node saw acked, client and host), `acks` (acks written), `logDelivered` (log messages injected), `readerRestarts`. Real metrics are Task 14. `clusterNode.holdAppend` (unexported, tests) runs before each client append and can hold it (`appendGate` in the tests stands in for an unreachable log while the session store stays reachable).
- Known limits: mochi writes the 0x91 for a packet ID with a PUBREC inflight directly, outside the pipe's order. Mochi's opposite collision stays, with or without a cluster: a client PUBLISH that reuses a packet ID of an outbound delivery still in flight makes processPublish delete that delivery's entry (a paho 5.0 client publishing QoS 2 to its own subscription loses about one flow in five on plain mochi). A failed append retried behind later ones of the same client can land after them. QoS 0 and QoS 1/2 of one publisher take different paths and are not ordered against each other.

## Admin reactions (admin.go)

Called by the host when keys, roles or tenants change; `events.NewReactor` drives the first three from keysmith and warden plugin hooks. Each bumps `Broker.changes` (an atomic counter a CONNECT compares, see OnConnectAuthenticate), then copies the matching states under the registry read lock and works on them after releasing it; a PermLoader call never runs under the registry lock. Work runs in the caller's goroutine. Before Start and after Stop they do nothing.

- `DisconnectPrincipal(principalID string, code packets.Code) int`: disconnects every live connection whose identity's `PrincipalID` equals principalID (5.0 clients get a DISCONNECT with code) and returns the count. Principal IDs must be unique across tenants (keysmith key IDs are TypeIDs).
- `ExpirePrincipal(principalID string, connectedBefore, at time.Time) int`: every live connection of the principal with `connectedAt` before `connectedBefore` gets `Identity.ExpiresAt = min(existing, at)` (under `reloadMu`) and its expiry timer set again; when it fires, the client is disconnected with 0xA0 like any expired credentials. Returns how many it shortened. Bumps `changes`, so a CONNECT in flight authorizes again. The reactor calls it for a key rotated with a grace window.
- `ReloadRole(ctx, roleID)`: reloads every live connection whose current grants came from roleID (the roleIDs its last Load returned).
- `ReloadPrincipal(ctx, principalID)`: reloads every live connection of that principal.
- A reload holds the state's `reloadMu`, calls `Perms.Load` with the stored identity and current tenant snapshot, compiles with the connection's raw client ID and CONNECT username, swaps the grants in, then prunes the subscriptions the new grants no longer allow: `Topics.Unsubscribe`, `cl.State.Subscriptions.Delete`, `Info.Subscriptions` decremented, and the badger hook's `OnUnsubscribed`, like an UNSUBSCRIBE without the UNSUBACK. A subscription survives exactly when a new SUBSCRIBE for it would pass (`Broker.canRead`, shared with OnACLCheck; the tenant's own `$SYS` always survives). Load errors: see PermLoader.
- Reload retries: a reload whose Load fails on an outage starts one retry loop per connection (`retryReload`), unless one is pending. It waits `retryBase` (1 s), doubling up to `retryMax` (30 s), and retries under `reloadMu` until a load works or `retryWindow` (2 min) has passed since the first failure; then the client is disconnected with 0x88 so it authorizes again on reconnect. A later reload that succeeds (or refuses) ends the pending loop (`st.retryStop` closed), and so does dropping the state (remove, sweep, takeover). `Stop` closes `retryQuit` (which also cancels a Load in flight) and waits for every loop before disconnecting clients; no loop starts after that. The three durations are unexported fields tests shorten; `pendingRetries` counts live loops.
- `disconnect` never lets the DISCONNECT write gate the close: the write runs in its own goroutine, and after `disconnectWait` (1 s) the client is stopped anyway, which closes the connection and fails a stuck write. Mochi's DisconnectClient writes before it stops the client and a write has no deadline, so a client that stops reading (while its own packets keep extending its keepalive) would otherwise block DisconnectPrincipal, UpdateTenant, a 0x87 reload and the admin call behind them. Shutdown disconnects clients in parallel for the same reason.
- `UpdateTenant(t *tenant.Tenant)`: stores a copy of t as the tenant snapshot of every live connection of t.ID, so OnPublish uses its limits from the next message; if `!t.Enabled` those connections are disconnected with 0x98. Call it after the tenant is stored and the resolver cache cleared (service.Tenants.Update does both), so a CONNECT that authorizes again reads the new tenant.
- Pruning a session (reconnect) also drops queued PUBLISH inflights outside the grants: `Inflight.Delete`, `IncreaseSendQuota`, `Info.Inflight` decremented, badger `OnQosDropped`. Mochi v2.7.9 already deletes a session's stored inflights on every takeover (the old client's `ClearInflights`), so the storage call matters only if that changes.

## Admin operations (admin.go)

For the host's admin API (the API checks the caller's permissions and limits first; the broker checks none). Each takes a Tether tenant ID and client IDs and topics as the tenant's devices see them, namespaces them itself, and never lists or touches another tenant's clients, sessions or retained messages. A tenant ID that is not a canonical tenant TypeID (`id.ParseTenantID` and `String()` round-trips), an empty client ID or one with NUL, and a topic failing `topic.Valid` (with `MaxTopicLength`) are `tether.ErrInvalidInput`; the two listings return nil instead. None holds the registry lock across a mochi call.

- `ClientInfo{ClientID, Username, DeviceID, Remote string; Connected bool; ProtocolVersion byte; Subscriptions []string; ConnectedAt time.Time; SessionExpiry uint32}` (json snake_case; ConnectedAt omitzero). `RetainedInfo{Topic string; Size int; QoS byte}`.
- `Clients(tenantID) []ClientInfo`: cluster mode adds every session of the tenant in the cell that this node does not have (`clusterClients`, `Sessions.Entries` with a 5 s bound): from its record, Connected when a node owns it (no Remote, no ConnectedAt); if the cell cannot be read only this node's are listed. Otherwise mochi's `Clients.GetAll()` (open connections and kept sessions of disconnected persistent clients) filtered to the tenant's `<tenant>/` prefix, inline client excluded, sorted by client ID; subscriptions un-namespaced and sorted. An open connection's Username, DeviceID, ConnectedAt and SessionExpiry come from its state; an offline session gets Username and SessionExpiry from mochi's client (read only once it is closed, since mochi changes them while open), and Remote is whatever mochi kept (empty after a restore).
- `Kick(tenantID, clientID) error`: the bounded `disconnect` with 0x98. No open connection (offline session included) or not started: `tether.ErrNotFound`. The session stays.
- `DeleteSession(tenantID, clientID) error`: `registry.beginDelete` sets a tombstone on the namespaced ID (a CONNECT for it is refused with 0x88 until the delete returns) and fails with `tether.ErrConflict` when another delete of it runs or another connection for it has already registered (it may be about to inherit the session). An open connection is disconnected (0x98) and DeleteSession waits up to `endWait` (`sessionEndWait`, 2 s; tests shorten it) for `ended`, so badger's OnDisconnect write is done. If the wait runs out, a connection still open is `ErrConflict`; a closed one (mochi skipped its OnDisconnect after a failed CONNACK write, a ghost) is deleted anyway. Then, unless mochi already removed the session (clean session) or holds another client under the ID (`ErrConflict`), `purgeSession`: `unsubscribe` everything (the routine pruning uses: topic index, session, `Info.Subscriptions`, badger `OnUnsubscribed`), `cl.ClearInflights()` (fires `OnQosDropped` on every hook), `Clients.Delete` if mochi still maps the ID to that client, badger `OnClientExpired`. The session does not come back after a restart. `beforePurge` (unexported, tests only) runs just before the purge. No session or not started: `tether.ErrNotFound`. A 5.0 delayed will mochi already queued is still sent. Cluster mode (ruling R7, `deleteClusterSession`): the client ID must pass `subject.CheckClientID`; the same tombstone; a session this node serves is marked deleting, disconnected (0x98) and waited for (its end evicts and writes nothing); a leftover closed local session is evicted; then `Sessions.Get`: absent is `ErrNotFound` (nil if a local session was just removed), owned by another node is `ErrConflict` naming the node (the control bus is Task 13), otherwise `Sessions.Delete` at the revision read (a lost race is `ErrConflict`).
- `Retained(tenantID, filter) []RetainedInfo`: `Topics.Messages` on the namespaced filter, un-namespaced and re-checked with `topic.Match`, sorted by topic. A leading wildcard matches no `$` topic, so `#` never lists the tenant's `$SYS`; `$SYS/#` does. Shared filters match nothing.
- `DeleteRetained(tenantID, topic) error`: refuses `$SYS` names in any casing; `tether.ErrNotFound` when nothing is retained there (or not started); otherwise an inline publish of an empty retained message, which makes mochi delete it and call badger's `OnRetainMessage(-1)`. Subscribers receive the empty message, as with any MQTT clearing.
- `Publish(ctx, tenantID, topic, payload, qos, retain) error`: ctx error first; topic must pass `topic.Valid` and not be under `$SYS` or `$share` in any casing (any other `$` name is a tenant topic, as over MQTT); qos 0 or 1, else `ErrInvalidInput`; not started: `tether.ErrConflict`. Inline publish of a copy of payload: no ACL check, no rate limit, not counted in (deliveries count out). Mochi takes an inline publish as received at QoS 0 and delivers at min(qos, subscription QoS); every delivery still passes OnACLCheck. Cluster mode: the topic must also pass `subject.CheckTopic` (1024 bytes), and a QoS 1 publish is appended to the log and waited for instead (ctx bounds it; its error is returned), then delivered by every node's reader.
- `DevicePublish(...)`: the same, for a message a device sent over HTTP: on success it also counts as a message in for the tenant (`Stats.MessagesIn`, `$SYS/messages/received`, `Metrics.MessageIn`). The caller has checked grants and spent the rate budget.

## Session expiry (expiry.go)

Mochi expires a closed 5.0 session after its `Props.SessionExpiryInterval`, but a 3.1.1 session only after the broker's cap. The `$SYS` goroutine also runs `expireSessions` every second (`sessionSweepInterval`): an offline 3.1.1 persistent session whose flagged `Props.SessionExpiryInterval` has run out since `StopTime` is purged like DeleteSession does (`beginDelete` tombstone, wait for `ended` or skip, `purgeSession`). Sessions restored from storage carry the property, so they expire too. `Clients` reports a 3.1.1 offline session's expiry from the same property. Cluster mode runs no sweep: mochi holds no offline session, and the key's TTL (the session's expiry, set by the last record write) ends a 3.1.1 session in the cell like a 5.0 one.

## Tenant $SYS (sys.go)

Every 10 s (`Broker.sysInterval`, unexported; tests shorten it before Start) a goroutine started by Start publishes, through mochi's inline client (`Server.Publish`, QoS 0, not retained), for each tenant with at least one open connection: `$SYS/<tenant>/clients/connected`, `.../messages/received`, `.../messages/sent`, `.../subscriptions/count`, `.../retained/count`, decimal payloads from `Stats`. Clients subscribe to `$SYS/#` (namespaced to `$SYS/<tenant>/#`) and receive `$SYS/clients/connected` and so on. Stop ends the publisher before it drains mochi. Mochi's own `$SYS/broker/...` (retained, every second) stays: no tenant filter can match it and OnACLCheck denies it to every network client.

## Mochi v2.7.9 workarounds

- `Server.Close` can deadlock: `Clients.GetByListener` read-locks twice, so a client added or deleted in between blocks it forever. `Stop` closes the listeners with a no-op closer, disconnects every client and waits for `Listeners.ClientsWg` before calling `Close`.
- When writing the success CONNACK or resending inflight messages fails, attachClient returns without OnDisconnect. When a tenant hits its connection limit, the hook sweeps that tenant's closed connections (`registry.sweepClosed`), releases their slots and retries. A reconnect with the same client ID also drops a closed previous owner (registry `bind`). A live connection's slot is never released by either.
