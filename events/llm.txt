# tether/events

Import: github.com/xraph/tether/events

Turns keysmith key changes and warden role changes into reactions on live MQTT connections. Imports keysmith (key, rotation), warden (role, assignment, id), mochi `packets`, `auth` and `cluster` (event kinds and payloads); it does not import `broker` (a broker satisfies `BrokerControl`).

## Handler

`Handler` is what the plugins report to:
- `KeyInvalidated(ctx, keyID string, disconnect bool)`: disconnect is true when the key may no longer be used (revoked, suspended, expired, or rotated with no grace window), false for a rotation hook that carried no record.
- `KeyRotated(ctx, keyID string, rotatedAt, graceEnds time.Time)`: the key was rotated at `rotatedAt` and its previous secret works until `graceEnds`.
- `RolesChanged(ctx, roleID string)`: a role was updated or deleted, or a permission attached to or detached from it.
- `SubjectChanged(ctx, subjectKind, subjectID string)`: a role was assigned to or unassigned from a warden subject (`"api_key"` for keysmith keys, `"user"`, `"service_acct"`).

Called synchronously from inside the engine call that made the change (and from keysmith's ValidateKey for `OnKeyExpired`). Implementations must be quick and must not call back into that engine. With NewReactor the reaction is done when the call returns; the cluster reactor returns once the bus has stored the change (each node applies it asynchronously on receipt), and can hold the engine call, a device's ValidateKey included, for up to `publishWait` (5 s) while the bus does not answer.

## Plugins

- `NewKeysmithPlugin() *KeysmithPlugin`: keysmith `plugin.Plugin` named `"tether"`. Register with `keysmith.WithExtension(p)` (construction only), then `p.MarkWired()`; `p.Wired() bool` reports it. `p.Bind(h Handler)` sets the handler later (nil unbinds); events before Bind are dropped. Hooks: `OnKeyRotated` gives `KeyRotated(id, now, rec.GraceEnds)` (`GraceEnds` falls back to `CreatedAt + GraceTTL`, `CreatedAt` to now). The rotation time is the hook's own `time.Now()`, not `rec.CreatedAt`: keysmith makes the record before it stores the new secret, so an old-secret CONNECT (or a cached validation) can complete in between, and only a cut-off taken after the store has the new secret catches it. A new-secret connection made in that gap also gets the grace end and reconnects then. It gives `KeyInvalidated(id, true)` when the record's `GraceTTL <= 0` (the old secret is dead at once and its connections cannot be told apart, so all of the key's connections go), and `KeyInvalidated(id, false)` with no record; `OnKeyRevoked`, `OnKeySuspended`, `OnKeyExpired` give `KeyInvalidated(id, true)`. A nil key is ignored.
- `NewWardenPlugin(h Handler) *WardenPlugin`: warden `plugin.Plugin` named `"tether"`, with `Bind(h)` and `MarkWired`/`Wired` like the keysmith one (nil h at construction leaves it unbound). `OnRoleUpdated`, `OnRoleDeleted`, `OnPermissionAttached`, `OnPermissionDetached` give `RolesChanged(roleID)`; `OnRoleAssigned`, `OnRoleUnassigned` give `SubjectChanged(a.SubjectKind, a.SubjectID)`. Warden emits no tenant; role IDs and key IDs are unique across tenants. Register with `warden.WithPlugin(p)` at construction: warden v1.8.0's `Engine.Plugins()` is nil unless the engine was built with a plugin or a decision cache, so runtime `Plugins().Register` can panic.
- Every hook returns nil and recovers a Handler panic (logged through `slog.Default()`). Keysmith stops dispatching at the first plugin error and would fail the admin call.

## Reactor

`NewReactor(evict func(keyID string), b BrokerControl) Handler`. `BrokerControl` is `DisconnectPrincipal(principalID, packets.Code) int`, `ExpirePrincipal(principalID, connectedBefore, at time.Time) int`, `ReloadRole(ctx, roleID)`, `ReloadPrincipal(ctx, principalID)`, all on `*broker.Broker`. `evict` is `(*auth.Keysmith).Evict`, may be nil.
- `KeyInvalidated(id, true)`: evict, then `DisconnectPrincipal(id, packets.ErrAdministrativeAction)` (0x98). Eviction comes first so a reconnect is validated by keysmith.
- `KeyInvalidated(id, false)`: evict only. Live connections stay.
- `KeyRotated(id, rotatedAt, graceEnds)`: evict, then `ExpirePrincipal(id, rotatedAt, graceEnds)`: every connection made before the hook ran (the previous secret's, plus any new-secret ones from the moment between keysmith storing the secret and the hook) ends at the grace end with 0xA0. Connections made with the new secret stay; one made with the previous secret during the window already expires then, because keysmith's validation reports the grace end (`auth.Keysmith`).
- `RolesChanged(id)`: `ReloadRole`.
- `SubjectChanged` with kind `"api_key"`, `"user"` or `"service_acct"` (warden's names): `ReloadPrincipal(id)`. Other kinds and empty IDs are ignored. Principal IDs are matched across kinds, which is fine while key, user and service account IDs are typeIDs with distinct prefixes.
- Empty IDs are ignored.

## Cluster reactor

For a broker that is one node of a cell (ruling R41). `Bus` is `Publish(ctx, kind string, v any) error` and `Subscribe(kind string, fn func([]byte)) error`, satisfied by `*cluster.Control`.

`NewClusterReactor(evict func(keyID string), b BrokerControl, bus Bus, log *slog.Logger) (Handler, error)`: subscribes `key.invalidated`, `role.changed` and `subject.changed` on bus (call it before the bus starts; nil bus wraps `tether.ErrInvalidInput`, a Subscribe error is returned). Its Handler methods drop what NewReactor ignores (empty IDs, subjects that never connect) and publish the rest as `cluster.KeyInvalidated{KeyID, Disconnect}`, `cluster.KeyInvalidated{KeyID, RotatedAt, GraceEnds}` (KeyRotated), `cluster.RoleChanged`, `cluster.SubjectChanged{Kind, ID}`, bounded by `publishWait` (5 s, not cancelled with the hook's ctx), and apply nothing: every node, the publisher included, applies each event once when it comes back. A failed publish logs at Warn (log, else `slog.Default()`) and applies the change here synchronously, exactly as NewReactor would, and (ruling R51) sends it again in the background with `cluster.Republish` (250 ms doubling to 5 s, each attempt 5 s) until the bus takes it, the bus stops (a bus with `Done() <-chan struct{}`, as `*cluster.Control`), or an hour has passed (the control stream's MaxAge); an error wrapping `tether.ErrInvalidInput` is not sent again. The other nodes then get the change once the bus is back, and this node applies it a second time when it comes back (events are idempotent). A control stream election (4 to 9 s) outlasts nats.go's own retries, so without this a revocation during one reached only this node.

On receipt: `key.invalidated` evicts the key at once on the bus goroutine, then on a goroutine `DisconnectPrincipal(id, 0x98)` when Disconnect, else `ExpirePrincipal(id, RotatedAt, GraceEnds)` when either time is set (a rotation; both zero shortens nothing, same as NewReactor), else nothing more. `role.changed` and `subject.changed` (connecting kinds only) run `ReloadRole` / `ReloadPrincipal` on a goroutine with a 30 s context (`applyWait`). Undecodable events are logged and dropped. The broker calls running on goroutines means two events can apply out of order; each reload reads current grants, so they converge.

`EvictTenantsOnUpdate(bus Bus, evict func(tenantID string)) error`: subscribes evict to `tenant.updated` (empty IDs dropped), for `service.Tenants.Evict` on every node. The broker applies tenant changes itself (`broker.Cluster.Control`); subscribe this before `broker.New` so the eviction runs before the broker's handler.

Tests: `reactor_test.go` has a `fakeBus` (keeps published events until `deliver`): `TestClusterReactorAppliesOnReceipt` (nothing applied before delivery; evictions in order at delivery, the broker calls once each after), `TestClusterReactorFallsBackWhenPublishFails`, `TestClusterReactorNeedsBus`, `TestEvictTenantsOnUpdate`. `cluster_test.go` (`newCellEnv`: two brokers over a three-server `clustertest` cluster, each with its own keysmith and warden engines, plugins, authenticator, tenant service and Control, sharing the tether, keysmith and warden memory stores, wired in the extension's order) covers `TestRevokeDisconnectsOnEveryNode` (revoked through node A's devices service: the device on B gets 0x98 within 2 s and its reconnect on B is 0x86), `TestRoleChangePrunesOnEveryNode` (a role narrowed through A's warden engine prunes the subscription on B, which then refuses it 0x87) and `TestTenantDisableAcrossNodes` (disabled through A's tenant service and broker as the API does: B's device gets 0x98 and B's tenant cache no longer lets it back).

Wiring (what the extension does, and what `events_test.go` does): build the keysmith plugin and the warden plugin unbound, pass them to the engines at construction, build `auth.NewKeysmith`, `perm.NewLoader` and the broker, then `r := events.NewReactor(authn.Evict, b)` and `Bind(r)` on both plugins. Device roles go through `service.NewDevices(store, tenants, keysmithEngine, service.NewWardenRoles(wardenEngine))`.

`service.Devices.SetRoles` applies only the role difference (assign added, then unassign dropped one by one through `service.WardenRoles`), so the reload after each event never sees a device without a role it keeps, and that role's subscriptions survive (`TestSetRolesKeepsSubscriptionOfKeptRole`).
