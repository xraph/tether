# tether/cluster

Import: github.com/xraph/tether/cluster

Runs Tether broker nodes as one cell over NATS and JetStream. This package holds the configuration, the NATS connection (embedded or external), the stream and bucket provisioning, the session store and the sentinel errors. The QoS 1/2 log (log.go, reader.go, replay.go) sits on `*Conn` too. The QoS 0 router (route.go, dedup.go) sits on `*Conn` too, and so does the membership service (members.go). Later tasks add the retained code.

## Config

`Config{Enabled, NodeID, Cell, Mode, URLs, Embedded, Heartbeat, Lease, Credentials, Replicas}` with snake_case yaml and json tags. `DefaultConfig()`: disabled, mode "embedded", heartbeat 2 s, lease 10 s. `Validate()` returns nil when Enabled is false. When enabled: NodeID is 1 to 64 bytes of `[-_a-zA-Z0-9]` (it becomes a KV key and a subject token), Cell matches `^[a-z0-9]{1,16}$`, Mode is "embedded" or "external", external needs a URL, embedded needs `Embedded.StoreDir`, `Embedded.Routes` needs `ClusterName`, and `ClusterName` or `Routes` needs `ClusterListen`, Lease must exceed 2 x Heartbeat, Replicas is 0 to 3.

`EmbeddedConfig{ServerName, ClusterName, Listen, ClusterListen, Routes, StoreDir}`. ServerName defaults to NodeID, Listen to "127.0.0.1:-1". List every other server in Routes: JetStream sizes its meta group from the route count, so a node given one seed route may elect a leader alone.

Names (all derive from Cell): `LogStream()` TETHER_LOG_<CELL>, `ControlStream()` TETHER_CTL_<CELL>, `SessionsBucket()` tether-sessions-<cell>, `RetainedBucket()` tether-retained-<cell>, `MembersBucket()` tether-members-<cell>. The KV backing streams are `KV_<bucket>`.

## Connect

`Connect(ctx, cfg, *slog.Logger) (*Conn, error)`. A nil logger discards. Embedded mode starts an in-process nats-server with JetStream (cluster routes when given) and connects in-process. External mode dials `URLs` (with the `Credentials` file when set). It returns once JetStream answers, or fails with an error wrapping `ErrUnavailable` when ctx ends (30 s when ctx has no deadline). The nodes of an embedded cluster only get JetStream once enough peers are up, so start them together; a node started alone waits.

The connection uses `nats.NoEcho()`: a node never receives its own core NATS publishes. The router relies on it. Reconnect is unlimited, 500 ms apart.

- `(*Conn).JS() jetstream.JetStream`, `NC() *nats.Conn`.
- `Healthy(ctx) error`: connected and JetStream answers; the error wraps ErrUnavailable.
- `Close()`: drains the connection, then shuts down the embedded server. Idempotent.
- `Replicas() int`: the replica count Provision uses. `Config.Replicas` when set. Otherwise min(3, servers): embedded mode counts 1 + len(Routes); external mode counts max(len(URLs), 1 + servers the client discovered) when the server reports a cluster name, else 1. A deployment that advertises nothing and runs two servers should set Replicas.

## Provision

`Provision(ctx, c, cfg, maxSessionExpiry) error` creates or updates, so every node can call it on start:

- TETHER_LOG_<CELL>: subjects `d.>`, file storage, MaxAge = maxSessionExpiry (0 = unlimited), duplicate window 2 min.
- TETHER_CTL_<CELL>: subjects `ctl.>`, file storage, MaxAge 1 h.
- sessions bucket: history 1, limit markers, LimitMarkerTTL 1 min.
- retained bucket: history 1, limit markers, LimitMarkerTTL 1 min.
- members bucket: history 1.

All with `Conn.Replicas()` replicas. Placement errors that clear while a fresh cluster's meta group fills (JetStream API codes 10005, 10008) are retried until ctx ends. The subjects are not namespaced by cell, so two cells cannot share a NATS account.

## Errors

`ErrLostCAS` (JetStream 10071 and 10164 both mean this; Sessions maps both, and the returned error also wraps the `*jetstream.APIError`), `ErrFenced`, `ErrUnavailable`. Messages start `tether/cluster: `.

## Sessions

One KV key per MQTT session in the sessions bucket, key `subject.SessionKey(tenant, clientID)`, value a JSON `SessionRecord{Owner, Epoch, Clean, ProtocolVersion, Username, DeviceID, ExpirySeconds, Subscriptions []SubRecord, Cursor, Will *WillRecord, QoS2In map[uint16]string, QoS2Out map[uint16]OutRecord, DisconnectedAt}`. `WillRecord.Props` is a `Props` (props.go): `User []UserProperty` (ordered, duplicate keys kept), `ContentType`, `ResponseTopic`, `CorrelationData`, `MessageExpiry` (seconds, 0 = none), `PayloadFormat *byte` (nil = absent). `Props.IsZero()` backs `omitzero`.

`NewSessions(c *Conn, cfg Config) *Sessions` (the bucket must exist, so Provision first). Every method checks the client ID with `subject.CheckClientID` and a non-empty tenant, and returns an error wrapping `tether.ErrInvalidInput` otherwise; no "" key is ever written. A write that loses wraps `ErrLostCAS`; a NATS timeout or no responders wraps `ErrUnavailable`. A call without a context deadline gets 10 s.

- `Acquire(ctx, tenant, clientID, nodeID) (rec, rev, existed, err)`: read from the stream leader, then CAS the record with Owner = nodeID and Epoch + 1. Absent key: created at epoch 1. A key holding only a limit marker or purge marker reads as absent but the create must name the marker's revision (JetStream refuses expected sequence 0 while the marker lives, until `LimitMarkerTTL`); Acquire does that. `rec` is the record as it was, with the new owner and epoch. A lost CAS is returned, not retried, except one retry of a create that lost over a stale marker read.
- `Update(ctx, tenant, clientID, rev, rec) (newRev, err)`: CAS, no TTL (this clears an earlier Expire).
- `Expire(ctx, tenant, clientID, rev, rec, ttl) (newRev, err)`: CAS like Update, as a raw publish to `$KV.<bucket>.<key>` with `Nats-TTL` (whole seconds, rounded up, min 1 s) and `Nats-Expected-Last-Subject-Sequence`. When it runs out the key becomes a limit marker; watchers see a purge with reason MaxAge.
- `Delete(ctx, tenant, clientID, rev) error`: CAS purge that leaves a marker for `LimitMarkerTTL`.
- `Get(ctx, tenant, clientID) (rec, rev, err)`: `tether.ErrNotFound` when absent, deleted or expired. Reads use the JetStream non-direct message get, so the stream leader answers and a node sees its own writes.
- `List(ctx, tenant) ([]*SessionRecord, error)`: a watcher pass over the tenant's keys, live ones only.
- `WatchOwned(ctx, nodeID, fn func(tenant, clientID string, rec *SessionRecord, deleted bool)) (stop func(), err error)`: one watcher over every key. It tracks the sessions nodeID owns (from this Sessions' successful Acquire, Update and Expire, and from records the watch reads with Owner == nodeID) and calls fn once when one changes owner or epoch (rec is the new record), or is deleted, purged or expired (rec nil, deleted true), then forgets it. This Sessions' own writes and deletes never fire. It returns after the first pass over existing keys. fn runs on one goroutine. Decisions compare revisions, with a write in flight parking the watch's event until the write's revision is known. stop is idempotent.
- One outstanding CAS per key per node: a keyed lock inside Sessions (entries freed when unused). JetStream refuses an expected-sequence write on a subject that has any write in flight (10164), so two writes of one key from one node must not overlap. A loser behind the lock meets an applied write (10071).

Internals worth knowing: `isLostCAS(err)` matches API error codes 10071 and 10164 and nats.go's `ErrKeyExists` and `ErrKeyRevisionMismatch`. `Sessions.afterRead` is a test hook that holds Acquire between its read and its write.

## Log

The cell's QoS 1 and 2 messages live in one JetStream stream, `Config.LogStream()`, subject `subject.Log(tenant, topic)` = `d.<tenant>.<enc topic>` (`$` topics stay under the plain tenant token). `Log` never creates the stream: Provision first. Everything that delivers a QoS 1/2 message to a session reads it through a `Reader` or `Replay`, so a tenant's order is the stream order.

`LogMessage{Seq, Tenant, Topic, Payload, QoS, Retain, Props, Origin, PublishedAt}`. Tenant and topic are not headers: they come back from the subject through `subject.DecodeLog`, which is lossless. Headers: `Tether-QoS` (1 or 2), `Tether-Retain` ("1" when set), `Tether-Origin` (node ID, omitted when empty), `Tether-Published-At` (unix nanoseconds), and the `Tether-Prop-*` headers of `Props`. Readers and Replay hand the same Payload and Props arrays to every caller on the node: do not modify them.

`NewLog(c *Conn, cfg Config) *Log` keeps a JetStream handle of its own for publishing, with a 30 s ack timeout so abandoned publishes free their bookkeeping.

- `Append(ctx, msg, msgID) (seq, dup, err)`: refuses with `tether.ErrInvalidInput`, before building a subject, an empty tenant, a topic over 1024 bytes (`subject.CheckTopic`), a QoS other than 1 or 2, and an Origin or msgID that is not a plain header value (no control characters, no space at either end). Async publish (`PublishMsgAsync`), waits for the ack future or ctx (10 s when ctx has no deadline). A non-empty msgID is `Nats-Msg-Id`: a repeat inside the 2 minute window returns the first sequence with `dup` true and stores nothing. `msg.Seq` is ignored; a zero PublishedAt becomes now. Unreachable JetStream, no ack in time and a closed connection wrap `ErrUnavailable`. When the publisher has 4000 acks outstanding Append waits and retries until ctx ends.
- `Reader(tenant, fromSeq, fn) (*Reader, error)`: ordered consumer with exactly one filter `subject.LogTenantAll(tenant)`. fromSeq 0 = only messages appended from now (resolved to last sequence + 1 at creation, so a consumer recreated before its first message does not skip any); otherwise the first tenant message at or after fromSeq. The server consumer exists when Reader returns. fn runs on one goroutine; an fn error is logged at Warn and the reader goes on (one bad message must not stall a tenant); an entry that does not decode is logged at Warn and skipped. `Position()` (atomic) is the sequence of the last entry the reader is done with (fn returned, or skipped), starting at fromSeq-1 (or the log's last sequence for fromSeq 0), never going back. `Stop()` is idempotent and returns promptly even while NATS is unreachable: it waits only for an fn that is mid-message (a mutex held while fn runs), after which fn never runs again. The iterator stop and the server consumer delete happen in the background (the ordered consumer's recreate loop can take 20 s or more to notice). Do not call Stop from fn.
- `Replay(ctx, tenant, fromSeq, toSeq, fn) error`: reads the tenant's messages in [fromSeq, toSeq]. The range is cut to the tenant's last message when the call starts (read with `GetLastMsgForSubject`), so a large toSeq does not wait for new messages; an empty range returns nil without a consumer. Calls for one tenant on one node share a consumer when the running one started at or below the newcomer's fromSeq and has not yet handed out a message with sequence fromSeq or more; otherwise the newcomer gets its own. Each call receives only its own range. fn runs on the consumer's goroutine (a slow fn slows calls that share it); an fn error ends that call alone with the error wrapped; when Replay returns fn is not running. ctx ends the call at once, also during an outage (a cancelled call gets no further fn calls); the consumer stops in the background, and is deleted, when no call uses it. A consumer that says it has caught up (pending 0) is double-checked against the tenant's last sequence before the calls waiting on it are ended, because a message appended after the server counted pending could fall in a later caller's range.
- `Log.consumers` (atomic) counts the server consumers the Log created, and `Log.heartbeat` sets the pull heartbeat (0 = nats.go default, 5 s); tests read and set them.

`Props` encoding (props.go, unexported `encode(nats.Header)` and `decode(nats.Header) error`): headers only for present properties. `Tether-Prop-User` is base64url (unpadded) of frames, per property uvarint(len key) key uvarint(len value) value, so order, duplicate keys, CR/LF and non-UTF-8 bytes survive. `-Content-Type`, `-Response-Topic` and `-Correlation-Data` are base64url of the raw bytes. `-Message-Expiry` and `-Payload-Format` are decimal numbers (the latter present means non-nil, so a pointer to 0 survives). A header that does not parse is an error from decode.

## Router

QoS 0 messages cross nodes by NATS subject interest, on core NATS (no JetStream). `NewRouter(c *Conn, nodeID string, deliver func(tenant, topic string, payload []byte, props Props)) *Router`. Each node holds one core subscription set per distinct (tenant, filter) with local subscribers and publishes every message once; NATS delivers it to each node with interest. Local delivery stays with the broker: the connection is NoEcho, so a node never receives its own publishes. Two Routers in one test process need two `Connect` connections.

- `Subscribe(tenant, filter) error`: one reference. The first one subscribes `subject.QoS0Filters(tenant, filter)` (two subjects for a trailing `#`: the parent and `parent.>`), later ones only count. `Unsubscribe(tenant, filter) error`: drops one; the last unsubscribes. An Unsubscribe with no matching Subscribe returns an error wrapping `tether.ErrNotFound` and changes nothing.
- Validation: the filter goes through `subject.CheckTopic` and `topic.Valid(filter, true, 1024)`, and an empty tenant is refused. `$share/...` filters are refused (Task 12 routes them). All of these wrap `tether.ErrInvalidInput`, and nothing is ever subscribed for a refused filter. A NATS failure wraps `ErrUnavailable` when it is a connection or timeout error.
- `Publish(tenant, topic string, payload []byte, props Props) error`: `subject.CheckTopic`, then `topic.Valid(topic, false, 1024)` (no wildcards, no NUL, not empty), then one `PublishMsg` on `subject.QoS0(tenant, topic)`. Headers: `Tether-Id` = `<node id>:<counter>` (the counter is atomic and starts at the clock reading at NewRouter, so a restarted node does not repeat ids inside the dedup window) and the `Tether-Prop-*` headers of `Props` (`Props.encode`). It does not wait; a message nobody has interest in is dropped by NATS.
- Receiving: tenant and topic come from the subject through `subject.DecodeQoS0` (an undecodable subject is logged at Warn and dropped). Props come from `Props.decode`; a header that does not parse is logged at Warn and the message is delivered with empty Props. A message without `Tether-Id` (a publisher that is not a Tether node) is delivered without deduplication and logged at Debug.
- Dedup (dedup.go): a message that matches two of a node's subscriptions (`a/+` and `a/#` for `a/b`) arrives twice. The second is dropped by `Tether-Id` within 2 s. 16 shards of id -> first seen, each also keeping its ids in arrival order so expired ids fall off the front on every insert (no sweeper goroutine). Capped at 2^18 ids; at the cap the oldest go first, so a burst larger than that can let a duplicate through. Memory follows the message rate times 2 s.
- deliver runs on NATS dispatch goroutines, one per subscription, so calls for different subscriptions can overlap. A slow deliver delays its subscription and past the nats.go pending limits NATS drops (QoS 0 allows it). Keep it short: hand off to the broker's queues. payload and props belong to deliver.
- Locking: the router's map lock (`Router.mu`) guards the route table, `closed` and each route's pin count, and is never held across a NATS call. Each route has its own mutex that serializes that key's first subscribe and last unsubscribe, so concurrent Subscribe/Unsubscribe on one key keep refs and subscriptions in step while other keys proceed. A route is pinned while anyone holds or waits for it and removed when idle with no references; `unpin` takes `Router.mu` while still holding the route mutex (order: route mutex, then `Router.mu`), so refs cannot change between the idle check and the delete.
- `Close()`: unsubscribes everything, idempotent, does not close the Conn, and is not a barrier for deliver: a message NATS already handed to a dispatch goroutine can reach deliver briefly after Close returns. After it Subscribe, Unsubscribe and Publish return an error wrapping `ErrUnavailable`. A Subscribe racing Close never leaves a subscription behind (the route is marked dead under its mutex).

route_test.go (package cluster, `startRouteNodes` gives n nodes, each with its own connection, on a three-server cell; `ready(a, b)` waits for b's interest to reach a's server with a probe subscription, which routes keep in order) covers routing across nodes, overlap dedup over three filters, `a/#` matching `a`, the `$` rule, tenant isolation, refcounts, NoEcho, the Props round trip, a foreign publisher, invalid input, Close, concurrent Subscribe/Unsubscribe and Close racing Subscribe under -race, and the dedup window and bounds with a fake clock.

## Members

`NewMembers(c *Conn, cfg Config) *Members` (the members bucket must exist: Provision first). Each node writes `{node_id, started_at, seq}` (snake_case JSON) under its own key (the node ID) in the members bucket every `Heartbeat`, with a plain `Put` (history 1), and watches every key. A renew succeeds when the KV put is acknowledged. A write times out after Lease/4, well under Lease/2, and the heartbeat goroutine and the monitor are separate, so a hung write cannot hold the fence back. Every duration is a local `time.Now()` reading compared with `time.Since`; KV timestamps are never used.

- `Start(ctx) error`: writes the first heartbeat, then starts the watch and waits until it has delivered the members that exist (the nil marker). ctx bounds Start only (10 s when it has no deadline); the goroutines run until Stop. A Stop during Start ends it. Once only. A missing bucket is an error that does not wrap ErrUnavailable; a timeout does.
- `Stop()`: idempotent; waits for the goroutines and for a callback that is running, and no callback runs after it returns. The node's key stays in the bucket (peers declare it dead after the lease), it is not deleted. Never call it from a callback.
- `OnFence(fn)`: once when no renew has succeeded for Lease/2. Checked every Heartbeat/4 (min 5 ms), so it fires within Lease/2 + one tick of the last renew, however the connection fails (blackholed, closed, JetStream down). `OnUnfence(fn)`: when a renew succeeds again after a fence. `Fenced() bool`.
- `OnPeerDead(fn func(nodeID string))`: once per peer that has not been seen for Lease + 2 s (`peerDeadMargin`, fixed; not configurable). "Seen" is the local receive time of a watch update with a higher revision (or a new started_at); a replayed update proves nothing. A peer heard from again is live again (logged, no callback) and can die a second time. A node never declares itself dead. Key deletions in the bucket are ignored, so the peer just ages out.
- While this node is fenced, or its watch has not shown its own heartbeat for a Lease, nobody is declared dead and every live peer's clock restarts each tick: a node that cannot see the cell must not call the cell dead, and gives its peers a full window once it sees again.
- `Live() []string`: sorted IDs of this node and the peers not declared dead; nil while fenced. `IsLeaderFor(deadNode) bool`: this node is running, not fenced, is not deadNode, and has the lowest ID (byte order) among the live nodes other than deadNode.
- Callbacks run one at a time, in transition order, on one Members goroutine and never under a lock of Members. A slow callback delays the ones behind it and Stop; hand real work to your own goroutine. Register them before Start.
- Locking: one mutex guards the state; no NATS call is made while it is held.

members_test.go (package cluster, `startMemberCell` provisions a three-server cell, `memberCell.node` starts a node, optionally through a `chaos.Proxy`; heartbeat 100 ms, lease 1 s, so peers die after 3 s) covers peers seeing each other, death after lease + 2 s (never before the lease) and revival, the fence within Lease/2 + slack when the node's NATS connection is blackholed through the proxy, one OnFence and the unfence after the heal, a fenced node declaring nobody dead, the lowest node ID being the only leader, Stop being final, a missing bucket and a closed connection.

## clustertest

Import: github.com/xraph/tether/cluster/clustertest

- `Start(t, n) []string`: client URLs of an n-server in-process JetStream cluster (a plain server when n is 1), random ports, `t.TempDir` stores, ready when the meta leader knows all n peers. Stopped at test end. About 1.5 s for three servers.
- `StartCluster(t, n) *Cluster`: same, with `Servers []*server.Server`, `URLs()` and `Stop(i)`.
- `FreePorts(t, n) []int`, `RouteURL(port) string`: for tests that run embedded nodes as a cluster.

Tests: conn_test.go covers the single and three-node embedded connect, idempotent provisioning on one and three servers, NoEcho, unavailable, and the Validate table. log_test.go (package cluster, `startLogs` gives one Log per node on a three-server cell) covers ordered reads with tenant isolation, `$` topics, QoS 2 dedup across nodes, fromSeq, handler errors and undecodable entries, Stop (also while NATS is unreachable, on a one-server `startOutageLog` cell), shared and separate replay consumers (through `Log.consumers` and the server's consumer count), replay ranges, settle, cancel, invalid input, a closed connection and the Props round trip. sessions_test.go (package cluster, on a three-server clustertest cell) covers the one-winner Acquire race with both error shapes, stale revisions, the keyed lock, expiry seen by a watcher, re-create over a marker, WatchOwned, the record round trip, List and Get, invalid input and isLostCAS.
