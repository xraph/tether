# cmd/tether

The standalone Tether server: `go install github.com/xraph/tether/cmd/tether@latest`, or `go build ./cmd/tether`.

It builds a Forge app with a grove database (SQLite by default, PostgreSQL by config) in the container, keysmith (`ext.Keysmith(keysmithext.WithDisableRoutes())`), warden (`ext.Warden(wardenext.WithDisableRoutes())`), ledger and chronicle when the config needs them (`productExtensions`, below), the Tether extension and the Forge dashboard extension, then calls `app.Run()`, which shuts down on SIGINT and SIGTERM.

## Flags and environment

- `--config <path>`: YAML config. Default `./tether.yaml` when it exists, else the defaults. A named file that is missing is an error.
- `--insecure-admin`: allow an empty token. The admin API mounts with no auth and the dashboard intents are served to anonymous requests (`WithInsecureDashboard`), as operators. It is the only way the binary makes operators by default: with the dashboard's auth on, a signed-in user is confined to their own tenant unless the config sets `tether.dashboard_operators: true`.
- `--version`.
- `--node-id <id>` and `TETHER_NODE_ID`: the node's ID in its cell (`tether.cluster.node_id`). The flag wins over the variable, the variable over the file. `applyCluster` applies it after the file is read and before anything starts.
- `TETHER_DATABASE_DSN`: the PostgreSQL connection string, overriding `server.database.dsn`. `applyDatabase` applies it after the file is read and validates the database settings. Never logged.
- `TETHER_ADMIN_TOKEN`: bearer token for the admin API, compared as SHA-256 digests with `crypto/subtle.ConstantTimeCompare`. A missing or wrong one is 401 with `WWW-Authenticate: Bearer`. A request it lets through gets a forge `extensions/auth` `AuthContext` with Subject `admin-token` (`adminSubject`), set on the forge context (`auth_context`) and the request context, so the REST API's audit events carry that Actor (ruling R24, `TestAdminMiddlewareSetsActor`). With `--insecure-admin` there is no middleware and the Actor is empty. Empty without `--insecure-admin` fails startup. The device endpoint `POST /tether/v1/publish` is not behind it (it uses HTTP Basic with the device key).

## Config

`tether.example.yaml` lists every key with its default. `server.http_address` (`:8080`), `server.sqlite_path` (`./data/tether.db`, used when the driver is sqlite), `server.database` (`driver: sqlite|postgres`, `postgresql` accepted for `postgres`, default sqlite, and `dsn`), and a `tether:` section that is `extension.Config` (`base_path`, `disable_routes`, `grove_database`, `dashboard_operators`, `broker.*`, `metering`, `entitlements`, `audit`, with `broker.data_dir` defaulting to `./data/sessions`). The binary decodes the file over `defaultConfig()` itself and hands the result to the extension with `WithConfig`, then points Forge's own config loader at the same file (for the `dashboard:` section). Environment config sources are off (the binary itself reads only `TETHER_ADMIN_TOKEN`, `TETHER_NODE_ID` and `TETHER_DATABASE_DSN`). Data directories are created.

`tether.cluster` is `cluster.Config` (off by default; see `extension/llm.txt` Cell). With it on in embedded mode, `applyCluster` refuses a cell of more than three nodes (itself plus more than two `embedded.routes`; the error says to run NATS yourself with `mode: external`, since every broker restart would otherwise be JetStream peer churn) and sets an empty `embedded.store_dir` to `./data/nats/<node id>`, which `newApp` creates, so nodes sharing a host never share JetStream data. External mode has no node cap. Nodes of a cell share tenants, keys and roles through the database: one SQLite file means one host, and a cell across hosts sets `server.database.driver: postgres` with the same DSN on every node.

## Metering, entitlements and audit

`tether.metering`, `tether.entitlements` and `tether.audit` (see `extension/llm.txt`, and `tether.example.yaml` for every key) are off by default. `productExtensions(cfg.Tether)` adds `ledgerext.New(ledgerext.WithDisableRoutes())` when `metering.enabled` or `entitlements.enabled`, and `chronicleext.New(chronicleext.WithDisableRoutes())` when `audit.enabled`, registered before Tether. Both find the binary's `*grove.DB` in the container (SQLite or Postgres, as `server.database` says) and migrate their own tables at Start. A part that is off registers nothing, so a binary with all three off is the same app as before. Their own sections (`ledger:`, `chronicle:`) in the same file reach them through Forge's config loader; routes stay off whatever those say, since the binary has no auth for them. `TestBinaryProductConfig` (all three on from a YAML file on SQLite: a tenant on a plan connects and publishes, one with none is refused, the tenant's create and connect reach chronicle) and `TestBinaryRegistersOnlyWhatIsOn`.

## Database

`database.go` holds `databaseConfig`, `applyDatabase`, `serverConfig.validateDatabase`, `openDB` and `describeDSN`. An empty or missing driver is sqlite, so a config with only `sqlite_path` is unchanged. Postgres needs a DSN that `pgxpool.ParseConfig` accepts (the driver's own parser, so a bad `pool_*` value fails validation); a DSN with the sqlite driver is an error (a cell must not silently fall back to a local file). Errors never quote the DSN, because pgx's password masking is best effort (a quoted password with an escaped quote leaks past it): `dsnError` classifies the parse error by type and drops it, saying "does not parse" or, for a `*fs.PathError` (a missing `sslrootcert`, `sslcert`, `sslkey` or `servicefile`), that a file the DSN names could not be read. `openPostgres` runs the same classification on any `*pgconn.ParseConfigError` from `drv.Open`, and other open errors name `user@host:port/database` from `describeDSN`. The pool connects lazily, so `openPostgres` pings and a down server fails there.

Each extension migrates its own schema at Start: keysmith (v1.9.0 and later), warden and Tether all run grove's orchestrator, which takes `pg_try_advisory_lock(1)` on a dedicated session, so nodes starting together take turns. `TestConcurrentOpenOnAFreshDatabase` runs the three migrations from eight pools on a fresh database; on keysmith v1.8.0 (plain unlocked statements) it fails with a duplicate key on `pg_type`. The lock is a session lock, so the DSN must reach PostgreSQL directly or through a session-mode pooler; transaction-mode pgbouncer breaks it. The SQLite directory is not created on postgres.

## For tests

`applyDatabase(cfg *config, envDSN string) error` is the database step on its own. `newApp(cfg config, token string, insecure bool, appOpts ...forge.AppOption) (forge.App, closeDB func(), err)` builds without starting. `applyCluster(cfg *config, flagNodeID, envNodeID string) error` is the cluster step on its own. `run(args, getenv, stdout, stderr)` is the whole program (`--version` goes to stdout, usage and flag errors to stderr). `vessel.Inject[*extension.Extension](app.Container())` is safe on a started app: the extension's Start is idempotent.

Warden's REST routes are off, and so is its dashboard role creation for anyone without a warden grant, so roles are made through Tether's own admin API: `POST /tether/v1/tenants/:tenantId/roles` (with `publish` and `subscribe`), `GET` to list, `DELETE .../roles/:slug`, `PUT .../roles/:slug/topics` to replace the grants. The same three operations are dashboard intents (`roles.list`, `roles.create`, `roles.delete`).
