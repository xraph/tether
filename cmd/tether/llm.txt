# cmd/tether

The standalone Tether server: `go install github.com/xraph/tether/cmd/tether@latest`, or `go build ./cmd/tether`.

It builds a Forge app with a grove SQLite database in the container, keysmith (`ext.Keysmith(keysmithext.WithDisableRoutes())`), warden (`ext.Warden(wardenext.WithDisableRoutes())`), the Tether extension and the Forge dashboard extension, then calls `app.Run()`, which shuts down on SIGINT and SIGTERM.

## Flags and environment

- `--config <path>`: YAML config. Default `./tether.yaml` when it exists, else the defaults. A named file that is missing is an error.
- `--insecure-admin`: allow an empty token. The admin API mounts with no auth and the dashboard intents are served to anonymous requests (`WithInsecureDashboard`), as operators. It is the only way the binary makes operators by default: with the dashboard's auth on, a signed-in user is confined to their own tenant unless the config sets `tether.dashboard_operators: true`.
- `--version`.
- `--node-id <id>` and `TETHER_NODE_ID`: the node's ID in its cell (`tether.cluster.node_id`). The flag wins over the variable, the variable over the file. `applyCluster` applies it after the file is read and before anything starts.
- `TETHER_ADMIN_TOKEN`: bearer token for the admin API, compared as SHA-256 digests with `crypto/subtle.ConstantTimeCompare`. A missing or wrong one is 401 with `WWW-Authenticate: Bearer`. Empty without `--insecure-admin` fails startup. The device endpoint `POST /tether/v1/publish` is not behind it (it uses HTTP Basic with the device key).

## Config

`tether.example.yaml` lists every key with its default. `server.http_address` (`:8080`), `server.sqlite_path` (`./data/tether.db`), and a `tether:` section that is `extension.Config` (`base_path`, `disable_routes`, `grove_database`, `dashboard_operators`, `broker.*`, with `broker.data_dir` defaulting to `./data/sessions`). The binary decodes the file over `defaultConfig()` itself and hands the result to the extension with `WithConfig`, then points Forge's own config loader at the same file (for the `dashboard:` section). Environment config sources are off (the binary itself reads only `TETHER_ADMIN_TOKEN` and `TETHER_NODE_ID`). Data directories are created.

`tether.cluster` is `cluster.Config` (off by default; see `extension/llm.txt` Cell). With it on in embedded mode, `applyCluster` refuses a cell of more than three nodes (itself plus more than two `embedded.routes`; the error says to run NATS yourself with `mode: external`, since every broker restart would otherwise be JetStream peer churn) and sets an empty `embedded.store_dir` to `./data/nats/<node id>`, which `newApp` creates, so nodes sharing a host never share JetStream data. External mode has no node cap. The binary keeps tenants, keys and roles in SQLite only, so the nodes of a cell run by this binary share one SQLite file, which means one host; a cell across hosts mounts the extension in an app on PostgreSQL.

## For tests

`newApp(cfg config, token string, insecure bool, appOpts ...forge.AppOption) (forge.App, closeDB func(), err)` builds without starting. `applyCluster(cfg *config, flagNodeID, envNodeID string) error` is the cluster step on its own. `run(args, getenv, stdout, stderr)` is the whole program (`--version` goes to stdout, usage and flag errors to stderr). `vessel.Inject[*extension.Extension](app.Container())` is safe on a started app: the extension's Start is idempotent.

Warden's REST routes are off, and so is its dashboard role creation for anyone without a warden grant, so roles are made through Tether's own admin API: `POST /tether/v1/tenants/:tenantId/roles` (with `publish` and `subscribe`), `GET` to list, `DELETE .../roles/:slug`, `PUT .../roles/:slug/topics` to replace the grants. The same three operations are dashboard intents (`roles.list`, `roles.create`, `roles.delete`).
